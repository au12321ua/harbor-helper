# harbor-helper 首版设计

本页保留该阶段的通用设计讨论；设计、实现和实际验收结论分别记录。

## 目的与成功标准

把已人工执行过的评测、候选版本对比与重跑流程工程化。首要目标是方便团队使用，而不是再证明研究闭环可行或保证模型分数提高。

运行位置已确定为统一机器。首版采用 Linux + Docker、SSH + CLI；维护者一次准备环境，成员通过默认方案运行，不手写 Harbor Job 或修改脚本。

验收数据集使用 Harbor Hub 私有 package `au12321ua/cad-bench@2`，本次已独立解析和下载两题并核对内容摘要。运行记录必须保存实际 task/dataset 身份，不把 `latest` 当作固定版本。真实执行必须来自该数据集，mock 仅用于生命周期故障与边界测试。

## 范围与假设

- 复用 Harbor 的 Job/Trial、Docker provider、agent 和 verifier，不另写任务执行器和评分器。
- 首版交付 CLI 初始化与诊断、后台提交、状态/日志/取消、报告/对比、版本固定与重跑。
- 支持内置 oracle 无模型基线和 opencode 模型实验；模型 endpoint 由维护者选择并配置。用户已澄清当前无自部署 vLLM，需要使用现成托管模型服务测试。优先复用现有 OpenAI-compatible 接入，服务须满足 opencode 所需的流式响应与工具调用；具体供应商兼容性在选定后实测。不自动选择供应商、发起未配置的付费请求或复用相邻项目的凭据。
- 无网页平台、分布式执行、完整 RL 训练、自研 gateway/sandbox、中途 agent 会话恢复或自动 promote。
- 共享机器面向受信任团队；首版不承诺跨用户强安全隔离或复杂 RBAC。每次运行隔离工作目录、配置和结果。
- 分数是否上升由实验决定；重跑保存配置不保证随机模型逐字重现。

## 使用流程与可观察行为

1. 维护者安装项目并初始化团队配置；诊断按所选方案检查 Harbor 版本、Docker/Compose、数据集权限、runtime 镜像及所需模型配置，给出实际修复动作。默认 oracle 不依赖模型，未配置模型作为可选能力说明，不应使默认 oracle 的诊断失败；显式 model 方案需校验其模型配置。检查不发真实模型请求，不打印凭据。
2. 成员选择默认实验方案，可覆盖 dataset、bundle、模型、尝试次数和并发；提交返回 run ID 和查看命令。普通提交不要求手写 Harbor 配置。
3. 提交后独立于当前 CLI/SSH 连接执行。全局运行容量受统一配置限制；容量不足时排队，避免多位成员分别达到各自并发后挤爆机器。
4. 状态包含 queued/running/succeeded/failed/cancelled（可增加 cancelling/recoverable 状态，但不能伪装完成）。可查看日志和取消；取消运行必须实际停止本次工作并清理本次容器，保留结果，不影响其他实验。
5. 报告展示逐任务评分、有效尝试数、基础设施异常与证据路径。CLI/worker 退出码不足以判断试验成功，须读取 Harbor Trial 结果与异常。
6. 对比两个 run，检查任务/评分版本、模型与采样条件是否可比，列出变更的 bundle/配置，展示逐任务和整体差异。不可比需说明原因，不能无声聚合成改进结论；缺失任务和异常不能当成有效零分。
7. rerun 创建新 run ID，使用保存的任务来源、bundle 内容与有效配置；原结果不被覆盖。首版整体重跑即可，选择性重跑失败 Trial 可延期并明确标注。

## 版本、配置与输入输出契约

- 输入：团队配置 + 实验 preset + 允许的 CLI overrides。团队配置与项目依赖共同固定 Python/Harbor 版本和接入方式、runtime image、数据集默认引用、资源/并发上限和非秘密模型连接信息。当前实现基线是项目 uv 环境的 Harbor 0.23.0，通过 Python API 接入，不依赖 PATH 中全局 Harbor 0.21.0；诊断与运行记录需显示实际 Python 和加载的 Harbor 版本。
- 模型凭据只来自明确的运行时环境或受保护文件引用，不写入 preset、manifest、命令参数、报告或归档；不读取相邻项目 secrets 来自动配置。
- 用户已指定现有凭据文件供模型测试使用：由受控启动进程直接加载到运行时环境，不将内容读取到 agent 上下文，不复制密钥文件或打印内容。凭据文件路径可作为明确的启动输入，默认 oracle 无需加载。文件加载、环境继承和脱敏先用假凭据检查；真实证据泄露扫描仅返回安全结论，不输出匹配内容。
- bundle 是可选的 skill/SDK/config 目录，提交时快照并记录 digest；同一个 bundle 在排队或执行期间被源目录修改不得影响已提交实验。注入方式沿用 Harbor/opencode 能力，SDK 放入可使用的环境，不声称只给文件打标签即已执行该版本。
- 输出：run ID、有效实验配置、bundle 快照/摘要、数据集任务身份、Harbor/opencode 版本、实际可取得的镜像身份、模型声明版本、状态、日志、原始 Harbor 结果、摘要报告和产物索引。
- 来源不能确认时标明未知，不虚报实际模型 checkpoint 或镜像 digest；重跑无法取回固定来源时明确失败/要求新实验，不悄悄换到 latest。
- 原始证据与报告分开保存，报告可重新生成；报告算法不绑定 CAD 的具体指标和测试文件。
- Runtime接入使用固定源码commit与匹配skill，agent/verifier兼容性须分别验证正例和负例。项目安装路径仍需固定构建输入、保存依赖清单与实际 image ID，并由产品 CLI 重验；镜像本机 ID 不称为 registry manifest digest。不得通过改题目或评分掩盖兼容问题。
- 当前 opencode 配置使用 `@ai-sdk/openai-compatible`；内部 provider 名称 `vllm` 是配置标识，不要求服务实际由 vLLM 部署。现有 `VLLM_API_KEY` 是显式凭据环境变量名，非供应商身份。非兼容接口、特殊认证或请求格式需在选定服务后评估适配，不能宣称所有托管服务开箱可用；服务不公开 checkpoint 时记录 unknown。

## 模块职责与最简单实现方向

| 部分 | 输入与输出 | 职责边界 |
| --- | --- | --- |
| CLI / 配置解析 | 用户选择 → 有效实验配置与 run ID | 默认值、校验、诊断和成员使用说明 |
| Run 管理 | 实验配置 → 状态、worker 生命周期和目录 | 持久状态、全局容量、取消、SSH 断开后运行 |
| Harbor 接入 | 固定任务与配置 → 原始 Job/Trial 证据 | 生成原生配置、调用已固定 Harbor、读取结果；执行与评分留给 Harbor |
| Bundle / 运行记录 | bundle 与来源 → 快照、摘要、manifest | 保存实际实验输入，不实现泛化 Artifact 平台 |
| 报告 / 对比 | 原始结果与 manifest → 可读报告 | 有效评分、异常、可比性和差异；领域评分仍由 verifier 给出 |

优先 Python CLI + 小型持久状态存储 + 单机 worker；允许 engineer 根据安装的 Harbor 能力选择最简单可靠实现。不要为首版引入 Redis、Ray、Kubernetes、通用插件框架或 REST 平台。

## 资源与失败处理

- 调试默认单个活动 Job、Trial 并发 1、attempts 1、基础设施自动重试 0；资源与 agent/verifier 超时继承数据集并由团队配置提供上限。
- 运行时预算至少能限制墙钟时间和尝试次数；token/费用只有能实际实施时才作为硬预算承诺，无法实施则明确显示不支持，不能仅记录一个数字就称已限制。
- startup、安装、下载、模型连接、agent 执行、verifier、清理等阶段失败要能定位；agent 超时按任务规则记录，基础设施错误单列。
- `exception_info=null`、日志目录存在或 artifacts 目录复制成功，不证明 agent 正常完成。记录可取得的 agent 进程退出事实、框架/环境异常与原始 verifier reward，分别展示；缺少退出事实时标未知，不能推定为零退出。通用状态判断不解析 CAD 特定错误文本或评分器私有 status 文件。
- 基础设施错误、已确认的 oracle/runtime 基线兼容错误与普通任务行为失败分开。后者可能按 benchmark 规则合法得到零分；不把所有工具非零退出或无效提交都排除成 infra_error。报告保留原始评分、有效/异常尝试数量及统计规则，不掩盖失败样本。
- 原始结果字段类型错误、数值无法安全统计等损坏输入须形成明确诊断，保留原文件并同步运行状态，不能抛出未处理异常后继续显示 succeeded；不得将错误字段强转为合法任务名或零分。
- worker 意外退出不能让旧 run 永久显示 running，也不能绕过总并发锁；至少能识别并标记 interrupted/failed，保留证据并提示重跑。跨 worker 防重复执行。释放容量前确认相关进程和本次容器已停止，或将仍在运行的任务计入容量；资源清理无法确认时，报告阻塞，不仅因调度锁已释放就启动下一批。
- 任何取消/清理仅作用于本项目本次 Job，不使用全局 Docker prune 或按名称宽泛杀进程。

## 验证顺序与人工验收

先做无需模型凭据的安装/CLI/生命周期验证，再用固定 CAD 数据集跑真实 Docker oracle 证明下载、镜像、产物交接和评分有效，随后验证 bundle 与 opencode 接入。模型连接或成员 SSH 访问需要人时，由主编排者汇总已完成内容、具体命令和剩余步骤后停下等待用户；不能把 mock 当作模型集成已通过。

机器验收通过后交给一位未参与搭建的成员：按简短说明完成提交、断开连接后查看结果、候选对比与重跑。checker 可以模拟新手阅读，最终真实成员参与仍单独标为待验收。

## 协作与完成协议

- 主编排者拥有本设计及验收基线，负责范围取舍和最终汇总。
- engineer 负责产品代码、配置、安装说明和实现验证，先交可用版本，再按 checker 发现修正。
- checker 先独立检查本设计可验收性，产品就绪后执行独立检查与真实命令，报告问题、证据和未验证项；审查报告放 `docs/checker-report.md`，不要与 engineer 同时改产品代码。
- 两位机器人使用工作目录 `/path/to/harbor-helper`，相邻 cad-bench 可只读参考，不修改其任务、评分或发布数据集。
- 完成/阻塞在当前会话用明确 @ 主编排者的消息回报；自查、实现完成、checker 通过、成员验收分别报告，不混为项目全部完成。

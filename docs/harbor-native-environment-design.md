核心职责：**Harbor 按 benchmark 作者定义管理环境；helper 管理来源、调度、缓存保留与结果。** 旧[任务环境方案](task-environment-design.md)的独立准备、产物固定和严格同镜像重跑已被用户否定，不作为本轮要求。

## 用户流程

管理员登记 benchmark 来源并验证访问权限；成员选任务、模型方案和实验参数后提交。helper 下载并保留任务快照、排队，轮到执行时由 Harbor 按原 Dockerfile、Compose 和镜像声明处理环境、运行、评分。第一次构建可能较慢，后续交给 Docker 使用已有镜像与构建缓存。无需先配置并验证一个统一业务镜像。

作者明确要求的变量或部署前置条件按其说明提供；缺失时报告任务与原因，不用 helper 默认镜像替代，也不继承旧 runtime 的镜像变量覆盖。镜像库存仅帮助诊断主机状态，不建立“镜像适用数据集”的配置关系。模型/key、队列、权限与容量仍由 helper 管理；既有 CPU/内存等执行限制如实记录，不将“忠于作者定义”说成没有部署约束。

## 缓存保留与资源清理

采用 Docker 现有缓存，不另建环境目录、缓存兼容规则或独立构建流程；不修改作者环境定义来追求缓存命中。运行结束清除本次容器、网络和临时卷，保留可复用镜像及构建缓存；成功、失败和取消均沿用现有归属核对与清理确认。

静态核查 Harbor `0.23.0`：`delete=True` 走 `down --rmi local --volumes --remove-orphans`；`delete=False` 走 `down`，会保留镜像，但单独使用不能保证卷已清理。helper 当前终态收尾按预先记录的精确 Compose project 删除并复查容器、网络、卷，没有 image rm 或 Docker prune。

单改 `delete=False` 不足：helper 的容器兜底删除当前没有 `-v`，依赖 project 标签删除卷也未证明覆盖所有匿名卷。建议只做窄的收尾调整：**保留 Harbor 的 `down --volumes --remove-orphans`，去掉 `--rmi local`，再沿用 helper 归属明确的终态复查。** 不启用 `keep_containers`；覆盖执行与独立评分环境，清理本次拥有的卷、不删除作者外部卷或网络。Harbor 本版未见单独保留镜像的清理参数，工程报告给出通过原生 `import_path` 继承 Docker backend、只调整 stop 命令的候选，不修改 build/start；具体实现由工程决定并定向验证，不改安装目录或重写环境生命周期。硬退出时兜底也要覆盖本次拥有的匿名卷，不能只复查有标签的卷就判完整释放。

默认 Dockerfile 路径仍可能每次调用 Compose build，由 Docker 判断层缓存；镜像输出 tag 可随 trial 改变，不以“第二次不调用 build”或“必须同镜像 ID”作为成功条件。镜像/缓存保留会占磁盘；本轮不加自动全机 prune 或缓存管理平台，后续空间清理由运维明确执行。缓存命中不能消除启动、安装和评分全部开销：删除容器后，其可写层中的代理安装和 bootstrap 仍可能重做，不为此制作替代作者环境的共享镜像，也不承诺固定加速倍数。

## 重跑与结果记录

重跑复制原 benchmark 任务快照及实验配置，再交 Harbor 按作者定义运行；不因为上次镜像丢失拒绝重跑。作者若使用可变 tag 或联网依赖，实际产物可变化，这是定义执行的结果，不由 helper 重新锁定为旧镜像。

结果保存来源版本/任务快照、模型与实验参数、Harbor 版本、评分和阶段信息。能取得时附加实际镜像引用/ID、构建日志或耗时；取得失败标明未知，不为记录环境而增加前置构建或阻断本来完成的实验。镜像 ID 不同可作为解释信息，不能单独导致拒绝重跑或比较；既有来源/评分完整性等比较条件仍保留。这不宣称两次完整运行环境相同。

## 现有配置如何收敛

新服务流程去除 dataset 必绑 `runtime_id`、准备阶段额外镜像 inspect/tag、`runtime_image_env` 统一别名注入及执行前相同镜像门槛。管理员以来源配置为主；Docker 发现保留为只读诊断。仍可保留来源下载/受理中的“准备”，但它不承担环境构建。

旧 runtime 对象、记录和快照不删除、不静默改写。历史通过 helper 注入镜像变量的实验如实标明旧覆盖，不能追认成忠于作者的原生运行。未终态实验在升级窗口核对后沿旧已受理契约处理。新服务提交和重跑均按作者定义；重跑旧覆盖实验时沿用 benchmark 快照与模型/实验参数，在受理页面和新记录明确说明旧 helper 镜像覆盖不再沿用，不修改父记录或宣称新旧环境相同。本轮不迁移用户现场，也不扩为旧 CLI 全面重写；其兼容影响在后续实施范围中核对。

## 后续最小验证

1. 来源登记及提交无需统一业务镜像；交给 Harbor 的 benchmark 文件保持原样，不注入替换镜像。
2. 同任务连续运行可利用 Docker 缓存，保留镜像/缓存；不要求同 ID 或完全跳过 build。记录真实构建输出与耗时，区分缓存和容器启动。
3. 成功、失败、取消后确认本次容器/网络/临时卷无残留，同时镜像/缓存不被结束清理删除；不同实验仍使用独立运行资源。
4. 原镜像不存在时原生重跑仍按作者定义执行；结果中的镜像差异/未知不单独阻断重跑或比较。历史覆盖记录与旧未终态不被改写。

当前是源码评估与设计；上述真实 Docker、Web 和迁移行为待后续变更验证，不把静态可行性说成运行通过。

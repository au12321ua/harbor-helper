# 一次登录与日常 CLI 使用

本页保留该阶段的通用设计讨论；设计、实现和实际验收结论分别记录。

用户已明确要求用代码继续完善可用性，并授权团队自行规划凭据保存方式；不再把“默认不改产品代码”当作本轮限制。本文区分用户要求、代理选定的实现取舍与尚待验证项，不代表用户逐项批准了技术细节。

## 目的与使用场景

成员希望输入一次 API key，随后一段时间内直接提交任务、查看过程与结果，包括退出 SSH 后重新登录。上一轮的 `hh_model`、`hh_stop_idle`、`hh_refresh_model` 和内嵌 Python 片段把产品职责转交给了使用者；重写说明没有解决这个问题。

已确认要求是：凭据输入和后台运行由产品封装，正常 `submit` 提交模型任务，后续通过 CLI 观测；所有辅助函数退出用户操作流程。终端输出应适合阅读，保留机器可解析的输出方式。

成功标准是成员只用正式 CLI 完成一次登录、提交、断开重连、查询、取消或重跑，不需要自行拼接环境注入、等待进程退出或执行扫描脚本。缺少配置或登录时给出具体修复命令，不能悄悄运行 oracle。

## 范围、预算与假设

继续复用已选模型服务、Harbor 0.23.0、预装 OpenCode 和现有单机调度、快照、报告与评分。不增加 Web 服务、多用户权限平台或新任务执行器，不改题目、评分和历史 run。

默认登录有效期选为 8 小时，可通过命令调整。这是代理选定的日常使用默认值，用户没有要求具体时长。账号与统一 team 仍由受信任团队共享；这次改动不提供成员身份隔离。

本轮验证使用假凭据、隔离的账号目录和 state、无付费模型 fixture，以及必要的 oracle。没有新的真实模型预算授权，不为了验证登录新增模型请求。之前的 A9/A10 模型证据保留，不能将它当作新登录生命周期的测试。

## 对外边界与可观察行为

维护者一次安装并准备模型、runtime、数据集。成员的日常流程为：

```text
harbor-helper auth login
harbor-helper submit
harbor-helper list
harbor-helper status <run-id>
harbor-helper logs <run-id>
harbor-helper report <run-id>
```

`auth login` 隐藏输入 key，也支持 `--key-file` 引用已有受保护文件；命令先显示选中的 team 与模型服务。登录只保存本地使用授权，不发送认证探测，不声称 provider 已验证。`auth status` 展示是否有效和到期时间，`auth logout` 结束本地登录。

`init` 或登录可以记录默认 team。解析优先级为显式 `--state`、环境变量、已选 team、已有项目 team 发现、系统默认；正常重连不再要求重复 `export`。已有项目 team 的发现必须明确显示选中对象，不能偷偷修改共享配置或转到另一个服务。

新 CLI 的裸 `submit` 默认选择模型，缺少模型配置或有效登录时，在创建 run、下载任务或启动 worker 前失败并给出下一步。oracle 用显式 `--agent oracle` 自检。历史 manifest、旧 run 的 preset 和 rerun 来源保持原身份；不以修改旧记录实现新默认行为。

登录到期后，新的模型提交和实际出队执行都被拒绝；已运行的任务继续执行并完成审计清理。排队任务若到期，形成明确的未执行失败，避免永久排队或后台绕过到期限制。查询、取消和收尾不应因登录过期失效。

凭据轮换和 logout 不能丢失活动任务的审计依据。最小方案在存在未终态任务时拒绝轮换或退出，并提示等待或取消；到期不会强制删除活动任务仍需的凭据。过期是本地新任务授权到期，不会撤销服务端 key。

实际运行使用过的来源在同一私有区作为历史审计记录保留，登录到期和 logout 只撤销新执行授权，不把历史审计材料作为新任务的凭据。logout 输出应说明历史审计仍保留，不能称为彻底抹除 key。未使用的会话不必长期保留；关联 run 和日志仍保留时，其审计来源继续可用。删除来源或外部引用文件改变后，相关历史扫描明确不完整，不能仍称全 clean。已有真实文件仍仅保存引用，不复制值。

整个 state 的扫描使用可取得的历史来源；缺所需来源时只报告安全计数和覆盖限制。每个新 run 的执行与收尾按它绑定的来源判断，不因为无关旧引用缺失使全部日常查询或新实验失效。安全状态和摘要仍可读取，不能确认安全的历史原始日志不读取或交接。

旧 idle scheduler 的凭据刷新由登录命令内部完成。`stop` 自己等待确定的旧进程退出，超时返回失败；用户不再定义等待函数。`recover` 自动加载收尾需要的凭据，`scan` 提供正式安全扫描入口，仅输出计数与结论。

默认输出为摘要与表格，包含 run ID、状态、有效评分数量和下一步命令；`--json` 保留结构化原始字段和既有退出码，项目自动化明确使用它。日志显示可读内容。查询、取消与再次执行在说明中分开。

## 关键取舍

凭据放在当前账号私有的专用目录，与实验 state、team.json、bundle 和证据归档分开。目录权限 0700、文件权限 0600，并核对所有者、链接和文件类型。交互输入可以保存在授权的本地凭据缓存中；这是受权限保护的本地存储，不承诺加密或抵御同账号进程。引用既有文件时只存路径和到期信息，不复制用户已经指定的真实 key。

采用限时本地缓存是为了复用现有进程模型，并支持 SSH 重连与 scheduler 重启；当前需求不值得增加专门的凭据代理服务。到期检查必须落在实际 worker 启动边界，不能仅由 CLI 做一次检查后让常驻 scheduler 无限继承旧授权。

模型默认是有意的行为变更：用户正常提交的目标是模型实验。没有登录时明确失败，oracle 必须显式选择。文档和现有自动化需同步，不能借由兼容旧示例继续让默认提交变成自检。

扫描实验 state 时不把专用凭据存储作为实验产物；其权限检查由登录模块负责。模型 key 仍不得进入 argv、非秘密配置、冻结输入、日志或报告。原有流脱敏、写入前 reason 处理和停写后审计继续生效。

## 模块职责与接口约定

| 模块 | 输入输出 | 职责 |
| --- | --- | --- |
| 登录与 team 选择 | 显式 team、输入或文件引用、有效期 → 安全登录摘要 | 保存和验证私有缓存、绑定服务、选择默认 team；不调用 provider |
| 凭据解析 | team/endpoint、用途（新执行或收尾）→ 内存凭据或明确错误 | 新执行要求有效授权，收尾可保留需要的过期凭据；不得返回 key 给展示层 |
| CLI | 用户命令 → 业务结果与终端/JSON 输出 | 选择模型默认、隐藏输入、自动凭据装载和脱敏、给出修复动作 |
| Run / scheduler | 固定任务配置与登录状态 → worker 或明确未执行结果 | 实际出队时校验、内部停止等待/恢复、容量与精确清理；不解释领域评分 |
| 展示 | 原有命令数据 → 表格/摘要或原 JSON | 只做显示，评分有效性和可比性仍由既有报告逻辑判断 |

## 实现草图

CLI 增加登录、扫描与输出选项；凭据生命周期单独封装并由 CLI 与 scheduler 共同使用。沿用已有文件校验、内存环境转发、流脱敏、PID+birth 身份确认、SQLite 队列和锁，不增加泛化会话框架。

固定缓存保存应采用权限明确的原子写入与锁，登录并发与停机等待需覆盖真实 OS 边界。具体文件名和函数签名由工程选择，不能影响上述可观察契约。

| 决定 | 原因 | 可见效果 | 实现位置 |
| --- | --- | --- | --- |
| 正式登录入口 | 凭据不应靠用户 shell 函数注入 | 输入一次后普通命令可用 | CLI 与凭据生命周期模块 |
| 出队校验有效期 | 常驻进程不能绕过到期 | 到期不新增模型执行，运行中正常收尾 | scheduler 启动边界 |
| 内部等待停止与恢复 | SIGTERM 返回不是停止完成 | stop/recover 无需辅助函数 | Run/scheduler 生命周期 |
| 模型默认、oracle 显式 | 日常目标是模型实验 | 裸 submit 不再误跑自检 | CLI 参数默认与校验 |
| 摘要与 JSON 两种展示 | 人与脚本都需要稳定入口 | 日常可读，自动化保留字段 | 展示模块与项目脚本 |

## 验证与待决事项

用独立 CLI 进程核对登录后提交、SSH 类重连、到期实际出队、活动收尾、轮换限制、错误权限、旧 scheduler 自动刷新、硬退出恢复、stop 等待、scan 安全和两种输出。provider 行为用无付费 fixture，oracle 验证原执行和评分链路。

实际登录与输入体验最后仍需用户复试，机器人不能替代 A11。缓存布局、锁与脱敏传播由实现和独立审查验证；若发现会改变存储或活动任务行为的取舍，应回报并更新本文。未公开的服务 checkpoint、费用和 token 硬限制仍未知或不支持。

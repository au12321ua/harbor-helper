# 08 实验集合与对齐比较

阶段：P1 · 来源：故事三集合与比较、A4、B8、B9

导航：[总览](00-overview.md) · 依赖：[评分](06-results-scoring.md)、[提交](04-plans-submission.md)

## 1. 对象与需求

| 编号 | 要求 |
| --- | --- |
| ANA-01 | 集合只保存运行引用，运行可属于多个集合 |
| ANA-02 | 集合可持续增删引用，显示创建者、用途与修订 |
| ANA-03 | 比较必须声明关注的变化因素并展示其他条件差异 |
| ANA-04 | 按任务身份对齐，缺失、失败、重复次数和来源可见 |
| ANA-05 | 分析快照固定运行清单、设置、结果版本和计算输出 |
| ANA-06 | 系统提供可计算差异，文字结论由人或 Agent 撰写 |

集合建议创建者可编辑、团队可读，跨批次添加不复制结果或产物。其他成员复制集合后独立维护；以后若需要共同编辑，再增加显式协作者权限。

分析快照包括 collection_revision、run_ids、result_revisions、focus_factors、alignment_mode、metric_contract、selected_tasks、aggregation_version、computed_summary、evidence_availability_at_creation。结果冻结后原始文件可能过期，快照继续提供计算值并显示证据可用性变化。

## 2. 比较前检查

| 目的 | 允许变化 | 应保持一致并核对 |
| --- | --- | --- |
| 模型评估 | 模型、提供商接入配置 | 数据集内容、任务范围、Harness、附件、资源、计分 |
| 附件 A/B | 指定附件内容或参数 | 模型、Harness、数据集、其他附件、资源、计分 |
| RSI 迭代 | 明确的实现或配置变更 | 基准、评测口径及其他控制条件 |
| 稳定性观察 | 运行时间与随机种子等声明因素 | 其他内容与资源配置 |

检查结果分为：

- **阻止直接汇总**：不同数据集内容、任务无法可靠映射、指标语义或单位不同、评分契约不兼容。
- **允许但警告**：资源差异、重复次数不同、部分任务缺失、观察到模型实际版本不同。
- **预期变化**：属于 focus_factors 的字段，仍显示具体差异。

默认不支持跨数据集版本映射；未来如加入显式映射，必须保存映射版本与任务内容差异。相同任务名称不足以证明同一个任务。

## 3. 对齐和缺失规则

默认任务键为 dataset_version_id + task_key。视图提供：

1. 交集视图：所有选定运行都包含的任务，进一步显示每侧实际获分覆盖。
2. 并集视图：所有涉及任务，缺少的一侧显示 missing_task。
3. 原始运行视图：保留每次运行原分母与统计，不拼接结果。

行级状态区分 missing_task、not_started、execution_error、scored、artifact_expired。产物过期不等于没有评分；同一行可以“有分数、无原始日志”。

重复试次按 repetition_index 展示，但统计比较默认先在任务内聚合；不假设不同模型的第 1 次具有严格配对随机性。每个任务单元显示计划数、已评分数、均值、标准差与通过率。

## 4. 部分重跑的合成视图

原稿建议把同配置的新结果合并观察。本次设计提出有显式 provenance 的“每任务取最新结果”模式，不修改源运行：

1. 用户显式选择同一来源链且核心条件一致的运行；先核对 comparison_digest 与逐字段差异。
2. 按任务选择 accepted_at 最新、该任务全部计划重复试次已评分的运行，整组使用该任务的 repetitions；不跨运行挑选最高分。
3. 较新运行该任务仍部分失败时，默认保留最近一组完整已评分结果，并显示较新失败警告；如无完整结果，呈现最新部分结果并标记 partial。
4. 每一行保存 source_run_id、trial_ids、selection_rule 和选择时间。
5. 明示这是集合中的合成分析，不能称为一个新的原始运行或完整的新 bench 执行。

此规则避免按单个试次挑分造成偏差；它是对原稿 A4 建议的具体化，状态为设计建议 D-008。用户可随时切回各运行原始视图。

## 5. 基本统计和差异

首期分析只提供样本量、均值、样本标准差、通过率与差值。只在指标、任务集合和聚合规则一致时给直接差值；条件不一致时先展示原因。

“差异显著”“模型提升”不由系统自动断言。置信区间、显著性检验、pass@k 与自动实验解释列为后续能力。

结论字段包含 text、author_user_id、pat_id（如有）、created_at、updated_at、revision。记录为“人工 / Agent 备注”，与 computed_summary 分开，避免把文字意见作为平台计算事实。

## 6. 分析快照与下一轮

快照建议仅从生命周期终结的运行创建，避免冻结时结果仍变化。创建后运行列表、设置和计算值不再更新；需修改时创建新快照并记录 parent_snapshot_id。文字结论的修改使用带作者的独立备注修订。

从分析中发起下一轮时，选择某个源运行执行重跑或修改后运行。将新运行加入可写集合需显式设置目标 collection_id；无权限时返回可复制集合的建议，不能绕过集合创建者权限。

## 7. 验收

- 同任务名、不同版本内容的运行不能直接给出 A/B 总分差。
- 一组运行缺一项任务，交集 / 并集视图均显示实际覆盖及排除范围。
- 部分重跑合成结果逐行可追溯，原运行汇总不变。
- 新运行加入集合后，旧分析快照仍保持原清单和原计算值。
- 原始产物过期后，快照显示历史摘要与证据不可用状态，不显示虚假的可下载入口。

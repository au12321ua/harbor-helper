# 02 数据集与环境准备

阶段：P0 · 来源：原稿故事一、A2、A4、A5、A8 / A9、B2 / B13、C4

导航：[总览](00-overview.md) · 依赖：[领域模型](01-domain-model.md)、[配置与附件](03-configuration-attachments.md)、[权限](09-identity-security.md)

## 1. 职责与边界

本模块把外部数据集转换为不可变版本、任务清单和准备规格，分别维护任务的版本准入与机器上的准备缓存。管理员首次准备成功，确认该内容及其准备方式可用后建立准入；缓存被回收不会撤销准入。

添加版本、首次准备及其失败重试仅允许管理员网页会话。已准入内容的缓存恢复由已受理运行自动触发；成员与 experiment PAT 无需另行申请管理员操作。附件安装同属运行准备，首期每个试次独立执行，见 [03](03-configuration-attachments.md)。read PAT 只可读取相关状态，不能提交运行。

首期仅实现 Harbor Hub 数据源。官方 Job configs 已确认 datasets[].ref 和 tasks[].ref 支持标签、修订或 digest，不能与 datasets[].version 混用；鉴权、清单字段、资源字段及下载行为仍需锁定版本接入验证。本地数据源列为待定扩展，不纳入 P0。

## 2. 需求分解

| 编号 | 要求 | 验收依据 |
| --- | --- | --- |
| DS-01 | 按作者 / 名称查找数据集，读取说明、版本与任务目录 | 搜索结果含来源与可用状态 |
| DS-02 | 添加时选择可解析的明确版本并固定内容 | 同名版本内容漂移时拒绝覆盖 |
| DS-03 | 保存作者参数、环境变量契约、默认资源及准备方式 | 网页表单和 SDK 获得相同定义 |
| DS-04 | 管理员首次准备及其重试，按任务建立准入依据 | 初次失败的任务仍被阻塞，成功证据保留 |
| DS-05 | 至少一个任务可提交时版本进入运行目录 | 默认选择全部可提交任务，包含已准入的冷缓存任务 |
| DS-06 | 按规格与位置复用缓存，回收不影响准入 | 缓存命中、失效和恢复均可解释 |
| DS-07 | 添加新版本形成独立记录 | 既有运行继续引用旧版本 |
| DS-08 | 已准入内容由运行自动恢复；相同缓存的并发请求共享恢复 | 单个等待者取消不终止其他等待者所需工作 |
| DS-09 | 区分暂态准备失败与固定内容不可得 | 前者允许受限重试；后者阻止新提交和原配置重跑，指出摘要 |

## 3. 导入流程

1. 搜索只返回外部描述，不建立业务版本，也不触发准备。
2. 管理员选择标签、修订或 digest。适配器将标签 / 修订解析为确切上游 digest，保存原始引用与 ref_kind；已给 digest 时直接作为上游内容身份。下载后另校验材料与本地清单摘要，不把解包目录哈希等同于 Hub digest。
3. 校验清单、任务键唯一性、资源单位、环境变量声明、文件路径和支持的运行环境。
4. 保存 DatasetVersion、Task、原始清单脱敏副本及转换器版本；凭据只保存引用。为每个任务建立 pending 准入记录。
5. 返回导入 Operation，随后按管理员选项创建首次准备操作。导入或首次准备失败的任务不进入可提交范围。标签不能被解析为固定 digest 时拒绝正式导入。
6. 同一数据集的同一引用和摘要重复导入返回已有版本；引用相同但摘要变化返回 CONTENT_REFERENCE_CHANGED，管理员必须以新内部版本明确记录。

作者参数分为 default、required、hard_constraints 和 description。资源建议值不自动视为不可违反的最低要求，适配器不能确定时标注 constraint_strength=unknown，详见配置模块。

## 4. 内部适配器契约

| 接口 | 输入 | 输出 / 失败 |
| --- | --- | --- |
| search | query、cursor、凭据引用 | 规范化摘要列表、next_cursor |
| list_versions | 外部数据集身份 | 明确引用、展示标签、可解析性 |
| describe_version | 数据集身份、明确版本 | 任务与参数契约、准备规格、内容标识 |
| fetch_content | 版本内容标识、暂存目标句柄 | 文件清单、内容摘要；不暴露业务目录 |

适配器分别映射鉴权失败、暂态网络错误、固定内容确实不存在、内容不匹配和清单不支持，保留脱敏上游证据与 request_id。一次超时、429、5xx 或无下载权限不构成“内容已永久消失”的证据。

Harbor 任务映射为 Task.task_key；Harbor trial 是 ExecutionAttempt 的执行证据，再归属平台 Trial；Harbor job 不等同于平台 Run。每个执行尝试仅生成一个任务 / 一个 Agent / 一次试次的 Harbor 作业。

需要调用 Harbor Python API 的目录与准备操作在独立 Runner 环境执行；服务端适配器通过 HTTP 或版本化 Runner 协议取得规范化信息，不 import harbor，见 [15](15-stack-harbor.md)。

## 5. 三类事实与准入规则

| 事实 | 建议字段与状态 | 变化含义 |
| --- | --- | --- |
| 版本准入 | admission.state：pending / admitted / revoked；含 revision | 管理员确认任务内容与准备方式可用；显式安全停用可撤销 |
| 固定内容可得性 | content.availability：unknown / available / unavailable；按必要内容摘要记录证据 | 是否能取得所需的同一内容；暂态故障不转为 unavailable |
| 本机准备缓存 | cache_state：absent / restoring / ready / stale；另记 last_restore_error | 是否持有经验证、可复用的成果；失败与回收不修改准入 |

准入按任务内容标识与已批准的 preparation_method_digest 记录，不依赖 location_id。首次成功保存准备方式、参数契约、固定输入 / 必需输出摘要、管理员及验证时间；成功证明不是七天后可删除的日志。准备方式或数据集内容改变需管理员确认新的准入记录。

已批准参数契约内的成员覆盖不会逐次触发首次准入；影响准备的合法参数参与实际缓存键。成员上传的附件不改写数据集准入或作者准备方式，按独立运行内安装处理。必填配置、评分契约、当前凭据与硬约束仍按配置和提交模块检查。

| 情况 | 新提交 / 原配置重跑 | 执行时行为 |
| --- | --- | --- |
| 首次准备未成功、准入已撤销或必要配置不完整 | 阻塞并指出管理员处理项 | 不以成员运行替代首次验证 |
| 已准入，缓存被回收或尚不在本机 | 允许，提示需要恢复 | 按固定内容自动拉取 / 构建，等待者共享结果 |
| 原内容仍存在，本次下载 / 构建暂态失败 | 不撤销准入；未来仍可提交 | 对受影响试次记录错误，按统一规则重试 |
| 已确认必要的固定内容不可取得，只能取得不同内容 | 标为“内容不可得”，两种提交均拒绝 | 若受理后才发现，受影响试次终结为内容错误 |

TASK_NOT_ADMITTED、TASK_ADMISSION_REVOKED、RESOURCE_CONTENT_UNAVAILABLE 是不同阻塞原因；PREPARATION_RESTORE_FAILED 是运行准备错误。内容错误包含 expected_digest、资源种类和验证证据，不能只提示“准备失败”。

可得性结合已验证的本地副本与固定来源判断：上游删除但本机仍有满足快照的确切内容时仍可运行。确认无可用副本且固定来源不再提供所需 digest，或取得的替代物摘要不符，才设置 unavailable。仅标签改指新 digest 时仍应尝试原 digest；禁止以新内容替换。再次验证取得相同内容后可以恢复 available；管理员决定长期停用或添加新版本，系统不得自动撤销准入或改写快照。

## 6. 准备规格与缓存有效性

~~~yaml
schema_version: 1
dataset_resolved_digest: sha256:...
materialization_digest: sha256:...
task_content_digest: sha256:...
preparation_method_digest: sha256:...
environment:
  base_image_digest: sha256:...
  build_definition_digest: sha256:...
  dependency_lock_digest: sha256:...
preparation_parameters: {}
adapter_version: "待接入验证"
environment_abi_version: "1"
~~~

spec_digest 覆盖影响准备内容的规范化字段；有效缓存键为 (spec_digest, location_id)，位置不进入内容摘要。上游 digest、镜像 digest 与本地材料摘要各自保留，不能交换使用。敏感值不进入可公开哈希，使用凭据引用及内部修订标识；仅用于下载授权的凭据轮换不改变内容身份。

复用需同时满足：规格一致、位置可访问、镜像 / 文件确实存在、摘要可验证、环境接口兼容且未回收。ready 记录不是文件存在的保证。可变镜像标签在首次准备时固定成 digest；重建还需满足快照固定的输出标识，不能只因为 Dockerfile 未变就接受不同结果。尚不能固定或重建必要依赖的准备方式必须明确阻塞，不能承诺严格复现。

~~~mermaid
stateDiagram-v2
    [*] --> absent
    absent --> restoring: 首次准备或运行恢复
    stale --> restoring
    restoring --> ready: 摘要验证并原子发布
    restoring --> absent: 失败或取消，保留错误
    ready --> stale: 回收或检查失效
~~~

准备 Operation 单独记录 downloading、pulling、building、checking 及 failed / cancelled / interrupted，不把 Operation 失败等同于撤销准入。目录分别统计 admitted_task_count、submittable_task_count、cache_ready_task_count；前两者还须区分显式停用和内容不可得。

默认范围命名为“全部可提交任务”（task_selection.mode=all_eligible）。解析时展开为具体列表，包括已准入的冷缓存任务；同时保存完整 bench 任务清单与排除原因。显式选择被阻塞任务返回逐项错误，不能悄悄缩小请求或宣称完成整个 bench。

## 7. 运行恢复与并发协调

1. 受理检查准入修订、必要配置与已知内容阻塞，不要求本机已有 ready 缓存。快照保存准入依据和固定准备规格，缓存观测单独返回。
2. Worker 在短事务内确认缓存未被回收认领并取得使用 pin，再验证实际内容；验证失败释放 pin 并标记失效。缺失时通过准备协调器，按缓存键原子创建或加入唯一活动恢复 Operation。Operation 有独立租约、generation、service_epoch 和等待者列表，不归属于首个运行。
3. 同一键同一时刻仅有一个拉取 / 构建，等待试次共享进度、结果或失败。构建资源只预留一次，等待者不重复占构建 CPU / 内存，不为等待预占模型提供商槽位。构建进程和资源按实例 / 恢复 Operation 标记，不能被某个等待运行的取消清理误删。
4. 一个等待者取消或到期只移除自己的引用；其余等待者继续。无等待者时可取消恢复并清理；独立恢复阶段有有限超时。新的等待者与取消并发时，通过事务重检租约状态，不能加入正在销毁的 generation。
5. 验证摘要后原子发布成果。有效租约与 generation 校验通过才更新 ready；从恢复 pin 交接给各试次使用 pin，避免发布与使用之间被回收。迟到或失去租约的结果不能覆盖新缓存。
6. 每个恢复 Operation 只做一次尝试，不另设内层重试。失败映射到各等待试次当前 ExecutionAttempt，统一走 [06](06-results-scoring.md) 的预算和退避；同轮重试仍合并为一个恢复，加入者不重置退避或已有尝试计数。未来新运行可触发新的受限恢复，不因历史暂态失败永久阻塞。

等待、恢复、试次容器创建与附件安装均包含在运行总时限内，不创建额外 Run、不消耗额外 PAT 提交额度。阶段超时只终止该等待者，不自动终止其他运行共享的恢复；共享恢复自身的超时或失败则通知所有当前等待者。

每个试次从准备成果创建独立可写容器，不共享可写工作目录。附件 bootstrap 只在本试次容器安装，不写入共享数据集缓存。系统内部身份只执行已受理、已批准的固定规格，审计关联原用户、PAT、运行与恢复 Operation，不能借自动恢复添加版本或执行任意宿主命令。

## 8. 回收、重启与恢复

缓存按配额和 LRU 回收。清理器在短事务内检查使用 pin、恢复租约和发布状态，标记回收后才删除，避免新使用者与删除竞争；完成后只写 stale，保留准入、内容标识、验证证据和历史。磁盘低水位仍可全局阻止新受理，不能把“允许冷缓存提交”理解为绕过空间限制。

服务重启对恢复进程、租约和标签对账，终止旧进程并清理未完成临时成果；已完成缓存经校验可保留。旧在途试次按 [05](05-scheduling-execution.md) 标记中断，自动恢复缓存不构成恢复原运行执行的授权。异机恢复保留准入证明，但新 location 的缓存须重新验证或恢复；环境 ABI 不兼容返回具体阻塞，不静默撤销准入。

## 9. 验收场景

- 三任务首次准备成功两个：仅两项准入，可提交范围为 2/3；管理员重试第三项成功后新解析为 3/3，旧快照不变。
- 回收已准入任务镜像后，成员和 experiment PAT 直接提交 / 重跑；按原 digest 恢复，无管理员动作，准入不变。
- 多个试次等待同一缓存，只执行一次成功恢复；取消一个等待者不影响其他等待者，构建容量只计一次。
- 下载暂态失败后受限重试，记录各受影响试次错因而不撤销准入；构建输出不同或原内容确定不可得时，新提交和原配置重跑均被阻塞并列出摘要。
- 上游缺失但本机确切副本仍在时可执行；超时、限流、鉴权失败不被误判为永久内容消失。
- 管理员 PAT 仍不能导入或发起首次准备；成员 / experiment PAT 的运行可以自动恢复缓存和安装附件。

## 1. 模块职责与需求

| 编号 | 要求 |
| --- | --- |
| RUN-01 | 实验方案可保存和修改，运行引用其修订而不受后续修改影响 |
| RUN-02 | 提交前可展开任务和批次，查看配置、估算规模和阻塞项 |
| RUN-03 | 受理原子写入运行、快照、试次、队列和操作记录 |
| RUN-04 | 支持单次与成组提交、取消未完成部分、按失败项重跑 |
| RUN-05 | 强制执行运行时限、任务 / 试次 / 并发限制与 PAT 总提交数 |
| RUN-06 | 重跑和修改后运行均创建新运行，保留来源与差异 |

> M5 第四阶段的实际做法（重跑如何固定原配置、方案作为解析的一层、批次只做显式列表）见 [实施记录](records/m5-configuration-submission.md)“M5 实施记录（第四阶段）”。

方案建议采用创建者可写、团队可读；其他成员先复制再修改。管理员可停用违规方案，普通内容修改仍遵循创建者归属。归档只影响新选择，不删除运行关联。

## 2. 预检与受理边界

预检返回三类检查：

- **配置检查**：字段、参数、任务范围、内容摘要和附件兼容性。
- **执行条件检查**：任务准入与必要配置、固定内容可得性、资源引用、凭据、执行器兼容性和主机可承载性；另列本机缓存观测与恢复计划。
- **受理检查**：身份、PAT scope / 期限 / 额度、维护模式、存储水位与规模限制。

Worker 暂时忙不构成受理失败，可排队；所有 Worker 离线、系统维护或磁盘不足时返回不可受理原因。某试次需求超过所有本机 Worker 的静态容量时必须拒绝，不能永久挂在队列里。

预检不占用额度。网络探测结果只作观测，不保证稍后模型提供方可用。受理失败返回结构化 blockers，不创建“半个运行”。

已准入任务的缓存缺失或失效仅产生 restore_cache 提示，不拒绝提交，也不要求管理员重新准备。首次准备未成功、准入已撤销或必要配置缺失时阻塞；有证据确认必需内容的原 digest 不可得时，以 RESOURCE_CONTENT_UNAVAILABLE 同时阻止新提交与原配置重跑。一次超时、限流或鉴权失败不能被记成永久内容不可得；现有凭据不可用仍可作为独立 blocker。

## 3. 单次提交事务

1. 认证主体，规范化请求并计算请求摘要。
2. 按主体、动作和 Idempotency-Key 查找已有受理结果；同键同内容返回原响应，同键不同内容冲突。
3. 解析配置或校验 resolution_id，固定内容并展开明确任务列表。
4. 在短事务内重新确认主体有效、PAT 未撤销 / 未过期、引用和准入修订未变、已知内容未被标记不可得、额度与受理状态允许；与并发撤销准入保持一致。
5. 写 Run、RunSnapshot、Trial、WorkItem、Operation、幂等记录及审计事件；PAT.accepted_runs 增加 1。
6. 提交事务后返回 202、run_id、operation_id 和查询入口；调度器异步领取。

每个任务按 repetitions 创建计划试次，总数 N = 选定任务数 × repetitions；不得执行时再随意扩展任务。自动重试增加 ExecutionAttempt，不能增加 N。

若请求在受理后响应丢失，重试得到原记录。成功取消、运行失败或产物过期不返还 PAT 提交额度，额度代表实际受理次数。

## 4. 成组提交

设计建议：P0 支持显式配置列表和受限的笛卡尔积展开，受理采用全有或全无的事务。

预览返回批次运行数、每运行任务数、计划试次总数、重复配置提示、阻塞项、PAT 需要消耗的运行额度和资源估算。预览不能把费用估算标为强制保证。

批次中任一配置不合法或额度不足时，整批拒绝。成功时一次创建 Batch、批次 Operation、所有 Run 与各自 Operation，并消耗与运行数相同的额度。展开规模超过 D-011 上限时在事务前拒绝。

执行阶段各运行独立；一个运行失败不取消其他运行。批次完成表示所有成员生命周期终结，另返回 finished / cancelled / interrupted、scored_trials、error_trials 等计数。取消批次通过批次 stop_requested 阻止其成员再被派发，并通知已领取项取消。

## 5. 额度、时限与停止条件

| 限制 | 归属 | 生效时点 | 达到后 |
| --- | --- | --- | --- |
| 任务数、计划试次数 | 运行 / 团队硬上限 | 预检和受理 | 拒绝超限请求 |
| 最大并发 | 运行、成员、PAT、团队、提供商 | 每次领取 | 等待容量，不改配置 |
| 单试次执行超时 | 快照 | Agent 执行开始计时 | 按评分契约处理超时与验证 |
| 验证 / 准备阶段超时 | 快照 | 对应阶段开始 | 记具体错误，释放资源 |
| 总运行时限 | 运行 | 建议从 accepted_at 起计，包含排队、缓存等待 / 恢复与附件安装 | 停止新派发，终止在途项并收尾 |
| PAT 总提交数 | PAT | 原子受理 | 拒绝新增，不取消已受理项 |
| PAT 有效期 / 撤销 | PAT | 每次 API 请求及受理 | 阻止后续调用；已受理项继续，需另行取消 |

原稿要求连续迭代上限，设计建议用一个专用 PAT 的 run_limit 加 expires_at 限制无人值守提交，不新增“迭代轮次”对象。这里统计的是运行数；一次批次含多个配置会消耗多次。网页批次使用显式列表与规模上限，网页不自动开展无限迭代。

PAT 额度 / 有效期用于受理授权；运行总时限用于终止既有工作。这两个限制不能相互替代。提供方实际调用费用与 token 可观测但不作为首期强制金额预算。

运行内缓存恢复和附件安装不创建额外运行，不再次扣 PAT 提交额度。多个运行等待同一恢复时，各自总时限继续计时；一个运行到期仅解除自身等待，其他等待者按 [02](02-datasets-preparation.md) 继续。

## 6. 取消与完成竞争

取消请求幂等：未完成运行写 stop_requested；未领取试次标记 state=not_started、reason_code=USER_CANCELLED，已领取试次进入取消协议。运行已有终态时返回当前结果。

以服务端首次接受的终态为准：取消生效前已接受的有效评分保留；生效后到达的普通结果不再改变该试次终态，可作为迟到证据归档。正常执行允许部分已评分、部分取消同时存在。

总时限结束同样走停止协议，原因使用 RUN_DEADLINE_EXCEEDED；保留已完成结果。收尾上传和清理有独立的有限宽限期，不能因清理失败让运行无限处于 running。

## 7. 后续操作

| 操作 | 配置来源 | 允许变化 | 来源记录 |
| --- | --- | --- | --- |
| 全量重跑 | 原不可变快照 | 新运行身份、绝对时间、当前凭据值 | relation=rerun，source_run_id |
| 部分重跑 | 原快照 | 显式缩小任务范围，保留原 repetitions | 任务选择、每任务原错因、原运行 |
| 修改后运行 | 原快照导入编辑 | 任何合法配置变化 | relation=modified，规范化差异 |

重跑不能重新合并团队默认。本机镜像、任务内容或构建缓存被删，但能按原标识恢复时，允许创建新运行并自动恢复。已确认原标识无法满足或只有不同内容的替代物时，拒绝并指出具体 digest；不能用最新标签替代。权限、准入撤销、凭据有效性、容量、额度与当前硬策略仍照常检查，缓存可恢复不豁免这些限制。

固定内容在受理后才确认不可得时，受影响试次记录内容错误并停止盲目重试；不撤销其他任务准入，不覆盖原快照。提交者可以修改配置后创建新运行，管理员决定停用任务或添加新版本。

首期部分重跑以任务为粒度：某任务只要存在未完成或失败的计划试次，可选入重跑；该任务的所有 repetitions 重新执行，不只补某个重复序号。这样每个新运行自身仍有完整试次计划。若未来需要逐试次补跑，另设选择协议。

原运行与重跑独立汇总，原评分不被补写。P1 集合可形成带来源的合成视图，规则见 [08](08-collections-comparison.md)。

## 8. 默认值建议与可解释性

初始建议为总运行时限 72 小时、PAT 默认有效 30 天且上限 1000 个运行；团队可收紧，用户可下调。它们是 D-011 的待确认初值，UI 和能力接口必须返回实际值。必须有有限上限，不能用无限作为缺省。

每个操作都返回下一步入口：查看运行、查看阻塞字段、取消、重跑、修改后运行、下载已完成证据。权限不允许的动作不显示为可执行，但隐藏按钮不能代替服务端授权。

## 9. 验收

- 两个并发请求争夺最后一个 PAT 配额，只受理一个；同幂等键重试不重复扣减。
- 批次中一个配置失效，全批无运行、无试次、无额度消耗。
- 取消时一部分已评分，结果保持；其余试次有明确未开始或已中断状态。
- 原运行部分失败后只选择失败任务重跑，创建新运行，任务范围和来源明确。
- 修改方案或团队默认后按原配置重跑，摘要保持；修改后运行展示差异。
- 已准入的冷缓存任务可由成员 / experiment PAT 提交和重跑；恢复与附件安装不另扣额度，确切内容不可得的拒绝发生在受理前时不扣额度。

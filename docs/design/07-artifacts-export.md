# 07 产物存储与导出

阶段：P0 · 来源：故事三查询与下载、补充 6、A8、C8

导航：[总览](00-overview.md) · 依赖：[评分](06-results-scoring.md)、[权限](09-identity-security.md)、[运维](12-operations.md)

## 1. 职责与需求

本模块保存和索引日志、会话、验证证据与输出文件，提供受权下载和批量导出。运行配置、评分摘要和产物索引属于业务元数据，不能与大文件一起按一周清空。

| 编号 | 要求 |
| --- | --- |
| ART-01 | 产物明确归属运行、任务、试次和执行尝试 |
| ART-02 | 逐项报告保存状态，收集失败不丢已确认评分 |
| ART-03 | 单项下载与批量导出保留来源、缺失和过期原因 |
| ART-04 | 默认 7 天后回收大文件，保留索引与过期标记 |
| ART-05 | 存储水位、准备缓存和导出包共同受控 |
| ART-06 | 存储通过接口访问，不要求 SDK 访问服务器目录 |

## 2. 内容分类与保留

| 类别 | 例子 | 建议保留策略 |
| --- | --- | --- |
| 业务元数据 | 快照、准入与首次成功证明、任务结果、指标定义、索引、来源 | 不自动到期；以后缩短须另定策略 |
| 原始产物 | 日志、会话、输出、验证报告、执行器原始结果 | 原稿已定默认 7 天 |
| 导出包 | ZIP / TAR 与导出清单 | 建议 24 小时，不延长原始产物 TTL |
| 暂存内容 | 未确认上传片段、失败导出中间文件 | 建议 24 小时，活跃任务除外 |
| 准备缓存 | 镜像、构建产物、依赖 | 空间配额 + LRU，不等同于产物 TTL |
| 应用运行日志 | 服务日志、Worker 诊断 | journald；建议 14 天，由宿主保留策略决定 |
| 审计与操作记录 | PAT 使用、受理、维护、权限操作 | 建议首期不自动删除 |

原始产物 expires_at 建议取所属试次 execution_terminal_at + 7 天，统一在 UTC 计算；试次已终结而上传延迟不重新开始七天。过期时间在详情与 SDK 中可见，建议到期前 24 小时提示。重要证据由用户在过期前导出并自行保存。

## 3. 存储布局与索引

~~~text
/var/lib/maestro/
  app.db
  artifacts/<run_id>/<trial_id>/<attempt_id>/<artifact_id>
  staging/<upload_id>/
  exports/<export_id>/
/var/cache/maestro/preparations/<spec_digest>/
~~~

这是服务端内部布局，具体配置和程序目录见 [12](12-operations.md)。API 只提供 artifact_id 与下载入口。数据库保存逻辑 relative_path、kind、MIME、大小、摘要、创建 / 到期时间、状态和缺失原因，不保存可直接供用户读取的宿主绝对路径。服务日志进入 journald，业务审计是结构化元数据；原始日志和产物不放进数据库。

同名文件可来自不同尝试，通过 artifact_id 区分。逻辑路径需规范化并拒绝绝对路径、空字节、路径穿越与符号链接逃逸；归档文件名由服务端生成，不能直接信任任务输出路径。

## 4. 写入与确认协议

1. Worker 申请上传句柄，声明归属、逻辑路径、大小和预期摘要。
2. 存储层写暂存文件，限制单项和单试次大小，计算实际摘要；不向消费者暴露半成品。
3. 验证后 fsync 文件，原子发布到正式目录；再提交索引的 available 状态。
4. 业务对象更新产物完成计数。重复确认相同 artifact_id 和摘要返回成功；不同摘要冲突。

数据库事务与文件移动无法形成一个事务，需有恢复对账：

- 文件存在而索引仍 uploading：验证上传记录后补确认，无法确认归属则作为孤立文件回收。
- 索引 available 而文件缺失：标记 unavailable，记录 STORAGE_CONTENT_MISSING。
- 上传失败：保留 failed 和原因，在暂存仍存在时重试上传；不重跑 Agent。

试次产物状态 pending / saving / complete / partial / failed / expired；同时返回 available_count、failed_count、expired_count。完整状态只是当前保存成功，不代表永久保留。

## 5. 查询与下载

下载先验证成员或 PAT 身份与读取权限。凭据文件、主密钥、Docker socket、宿主目录不属于业务产物；禁止通过通用文件接口读取。

| 内容状态 | 接口语义 |
| --- | --- |
| available | 返回或流式下载内容，支持校验摘要；可用 offset / length 分段读取（实现见 [14](14-decisions.md) M6 实施记录，Range 待需要时再加） |
| uploading | 返回尚未可用与重试提示 |
| expired | 返回 410 ARTIFACT_EXPIRED，仍可查询索引 |
| failed / unavailable | 返回 ARTIFACT_UNAVAILABLE 及原因 |
| 身份未知或无权限 | 统一按权限策略返回，避免暴露受限资源存在性 |

日志查询支持有界分页或 offset，不一次读入整个文件。执行中日志采用短轮询，P0 不要求 websocket。脱敏在写入前和返回前按基本规则处理，残余泄露风险见权限文档。

证据不设审计门（[14](14-decisions.md) U-10）：日志、阶段详情与产物经基本脱敏后即可查看，运行中也可查看，不因脱敏检查未完成或发现疑似残留而扣留整份证据。确认的泄露按凭据轮换处理，并可删除对应产物。

## 6. 批量导出契约

导出请求包含明确 run_ids、可选任务 / 产物 kind、是否包含原始文件。受理创建 Operation；服务端生成清单，即使部分产物已经不可用也可交付带警告的导出。

~~~text
export-<id>/
  manifest.json
  runs/<run_id>/config.json
  runs/<run_id>/summary.json
  runs/<run_id>/tasks/<task_key>/trials/<trial_id>/result.json
  runs/<run_id>/tasks/<task_key>/trials/<trial_id>/artifacts/<artifact_id>/<文件名>
~~~

目录名和文件名由服务端安全化生成。manifest 至少包含 schema_version、generated_at、服务 / 适配器版本、各运行快照摘要、任务对应关系、评分口径、每个文件的摘要与状态。缺失项列出 artifact_id、逻辑路径、reason、expired_at；不能只省略文件。

导出前取得有期限的读 pin，保护正在打包的内容。建议 pin 最长 1 小时；超时导出中止并释放，不能无限阻止回收。已经过期且尚未被删除的内容也不因导出重新变为 available。

导出包包含业务证据，不包含凭据、会话 cookie、PAT、主密钥或数据库内部密文。包在 24 小时后回收，下载入口报告到期时间。导出包本身也计入磁盘配额。

## 7. 回收、水位和竞争处理

清理器选择到期且无活跃读 pin 的文件，先标记 deleting，再删除文件，最后写 expired；失败可重试并记录错误。查询不得把 deleting 当可下载。

磁盘水位建议：可用空间低于 20 GiB 或 15% 时暂停新运行受理，低于 10 GiB 或 8% 时停止新派发；阈值为 D-011 初值，需按实际磁盘调整。停止受理时仍允许查询、取消和下载，已运行项尽力完成必要收尾；不能仅凭空间紧张删除未到期证据。

清理顺序：过期导出 / 暂存 → 到期原始产物 → 未使用准备缓存。缓存回收需原子检查使用 pin、活动恢复租约与发布状态，认领删除后阻止新使用者进入；完成后仅标记 cache_state=stale，保留准入与固定内容标识，不将其写成“内容不可得”。下一次已授权运行自动恢复同一内容，成员无需管理员重试首次准备。容量无法恢复时保持全局存储阻塞。

首次准备成功的证明及摘要保存为业务元数据，不依赖即将到期的原始日志。恢复发布到使用 pin 的交接必须连续保护；清理失败或外部误删只影响缓存观测，不能反向撤销准入。附件 P0 安装层随本试次容器清理，不混入共享数据集缓存。

## 8. 手动删除与回收站

用户决定（[14](14-decisions.md) U-08）：除主密钥外任何东西都可以删除；删除分两步；被删数据集关联的运行记录保留。本节其余规则为设计建议。

- **范围**：运行、批次、方案、集合、分析快照、数据集与版本、附件版本、模型配置、Harness、凭据、账户、PAT 和产物都可删除。第 7 节的到期回收是自动机制，与手动删除互不替代。
- **第一步，名义删除**：对象进入回收站，从列表和选择器中消失，不能再被新提交引用；已有引用仍能解析，并标明“已删除”。可从回收站恢复。
- **第二步，物理删除**：只能在回收站中执行，删除记录内容和文件，不可恢复。保留一条删除回执，记录对象身份、操作者和时间，使集合、分析快照、重跑来源能显示“已物理删除”，而不是悬空引用。实现中每个被删对象在 `deletions` 表有一行，回收站状态与回执共用这一行；各类对象物理删除的具体内容见 [14](14-decisions.md) 的 M6 实施记录。
- **引用方保留**：运行快照已冻结所需内容。物理删除数据集、配置或附件后，引用它们的运行仍可查看，显示快照中的名称与摘要；原配置重跑在受理检查中报告内容已删除。

以下由用户于 2026-10-23 确定（[14](14-decisions.md) U-19）：

- **运行**：排队或执行中的运行不能删除，须先取消或等其结束。
- **团队模型凭据**：有排队或执行中的运行在用时不能删除；紧急情况先停用，再取消相关运行。
- **PAT 与账户**：删除后立即失效，账户的会话和 PAT 一并作废。历史运行仍显示原用户名并标“已删除”。不能删除自己，不能删除最后一个管理员；账户还有排队或执行中的运行时不能删除。
- **回收站权限**：成员可把自己的运行放进回收站；回收站的查看、恢复和物理删除只由管理员操作。回收站不自动清空。
- **数据集版本**：物理删除时一并回收其准备缓存与镜像；仍被未删除版本使用的内容保留。

## 9. 验收

- 批量导出包含成功、未评分、已过期三种试次，manifest 准确标记，目录能映射回原运行。
- 文件保存失败但评分已确认，显示评分可用、产物部分失败，评分不回退。
- 模拟回收与下载同时发生，读 pin 有界保护且最后释放，无长期孤立文件。
- 七天后清理产物，配置、评分、索引、来源与操作记录仍可查询。
- 使用路径穿越、重复文件名或包外符号链接不能写出实例目录。
- 回收准备缓存后准入及证明仍在，成员与 experiment PAT 可直接提交；恢复和回收竞争不产生 ready 但内容被删除的成果。

## M2 实施记录

**2026-10-22，地基。** 以下是实现中的选择，均为设计建议层面，未经用户逐条确认；与原设计不同的已写明原写法和理由。

| 事项 | 原设计 | 实际做法 | 理由 |
| --- | --- | --- | --- |
| 数据库访问 | 15 / 01 建议异步访问配 aiosqlite | SQLAlchemy 2 Core + 标准 sqlite3，同步短事务；写事务一律 `BEGIN IMMEDIATE`；HTTP 处理放线程池 | 受理、额度、租约都是“先读后写”的检查，开头就取写锁最不容易出错；单机规模下同步短事务足够，异步驱动不带来实际收益 |
| 网页会话 | 01 的表中没有会话 | 新增 `sessions` 表，只存令牌摘要；CSRF 令牌由会话令牌派生，不另存 | 09 要求停用账户、改密码后立即失效，必须能在服务端撤销会话 |
| 首个管理员 | 12：受保护的一次性入口 | `maestro init` 打印一次性初始化令牌，数据目录里只存摘要；网页凭令牌创建管理员，之后因已有管理员而永久关闭 | 端口先被谁访问不能决定谁当管理员；重启也不会重新开放 |
| 主密钥文件 | 12：`/etc/maestro/secrets/master.key` 单个文件 | 移植 `dev` 的做法：`master_key_dir` 目录下按代次存 `master-<代次>-<随机>.key`，数据库只记当前代次、文件名和校验值；轮换在一个写事务里重新加密全部凭据，旧文件保留 | 原子轮换需要新旧两把钥匙同时存在；主密钥是唯一不删除的东西（U-08） |
| 凭据回显 | 01：返回“脱敏描述” | 不返回任何由值推出的内容（不显示末几位、不给摘要），只有管理员填写的说明 | 末几位也是泄露；09 也要求不保存值摘要到公开结果 |
| 幂等作用域 | 10：有效主体 + 动作 + key | 主体取用户，不区分网页和 PAT | 同一个人从两个入口用同一个 key，更可能是重试而不是两次实验 |
| 管理员重置账号 | 09 列出能力，未写方式 | 管理员生成一次性重置链接，用户自己设新密码；旧会话全部失效 | 管理员不经手他人密码 |
| 提交请求体 | 10：先解析配置，再凭 `resolution_id` 提交 | M2 临时直接提交数据集版本、任务选择、重复次数和并发；受理事务本身（幂等、主体与 PAT 复查、准入复查、额度、写入、审计）已按 04 实现 | 配置解析属于 M5；届时替换请求体，事务不变 |
| 数据集登记 | 02：管理员导入并首次准备 | M2 只有内部登记函数（测试和演示用），没有导入接口 | 导入与准备属于 M4 |
| 错误策略版本 | 06：平台策略带版本 | 暂记 `platform-0` 占位 | 真实映射随 M3 的执行器适配器确定 |
| 服务停止 | 05：重启后对账 | 服务被停止时运行保持“已领取”，下次启动统一标为中断；环境清理状态记为待处理 | 停止时不替执行器编造结局；按标签清理容器属于 M3 |
| 删除基线 | 13 第 2.2 节：M2 删除 `persistence/`、`service/data.py`、`access.py`、`setup.py` 与 JSON 状态 | 整个基线 `service/` 包、`persistence/store.py`、执行监督与 Worker（`execution/runs.py`、`worker.py`）、旧 CLI（`commands/`）、本机启动脚本、旧网页构建及对应测试一并删除 | 这些代码只能驱动被替换的旧服务，留下来既不能运行也会被误用；M3～M7 需要移植时读 `9ff43b5` |
| 删除与回收站 | 07 第 8 节（U-08） | M2 只有停用账户、撤销 PAT、停用凭据，没有删除和回收站 | 07 第 8 节的待定项（运行中能否删、删凭据的影响、删账户后如何显示、回收站权限）仍需用户确认，按 M6 实现 |

验证范围：pytest 覆盖空实例初始化与迁移一致性、WAL / 外键、密码与令牌、主密钥轮换及失败回滚、凭据绑定、权限矩阵（含管理员的 PAT 被拒）、幂等（同键并发只受理一次）、最后一个额度的并发争夺、受理与准入撤销竞争（F-26 的受理侧）、有效零分 / 缺评分 / 执行失败的区分、自动重试只增加执行尝试、取消保留已有评分、重启中断、迟到结果、运行时限，以及 E2E-RUN-01 的假执行器版本（只用 PAT 和 HTTP：能力 → 目录 → 幂等提交 → 轮询 Operation → 试次评分 → 下载产物并核对摘要）。网页另用 Playwright 在全新演示实例上手动走过一遍（初始化、提交并看完运行、PAT、管理页、成员视角），脚本在 `frontend/qa/smoke.spec.ts`，尚未进入自动门禁。未覆盖：真实 Harbor / Docker / Hub、配置解析与模型绑定、生成的 SDK（M7 才有，E2E 目前直接用 HTTP）、容量与提供商并发、按标签清理；网页使用绝对路径，配置了 `root_path` 的子路径部署目前不能用。

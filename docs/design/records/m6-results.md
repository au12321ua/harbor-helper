## M6 实施记录

**2026-10-23，结果与产物。** 用户指示先跳过 M5、另开会话并行做 M4，本记录只覆盖 M6。以下是实现中的选择，均为设计建议层面，未经用户逐条确认；与原设计不同的已写明原写法和理由。U-19 的删除规则照用户决定实现，不在此列。

| 事项 | 原设计 | 实际做法 | 理由 |
| --- | --- | --- | --- |
| 评分契约 | 06 第 2 节：每个数据集版本有管理员确认的契约 | 受理时把契约写进运行快照的 `policy.scoring`。数据集版本的 `manifest_json.scoring_contract` 格式正确时用它（来源标 `dataset_version`），否则用平台默认契约（来源标 `platform_default`）：指标 `reward`、越高越好、按“分数 ≥ 1”判通过、任务内先取均值再对任务取宏平均。格式不对的契约整体退回默认，不猜测通过规则 | 管理员确认契约属于 M4 的导入流程，届时写入 `scoring_contract` 即生效；Harbor 验证器对解出的任务写 1，阈值是显式的，不是“大于 0 即通过” |
| 汇总口径 | 06 第 5 节 | 运行列表、运行详情、`GET /runs/{id}/summary` 和导出包里的 `summary.json` 调用同一个函数。终态时“计划 = 已评分 + 按失败计 + 排除 + 未完成”；运行中另有执行中和排队数。“按失败计”的扩展策略未实现，恒为 0。排除原因优先取结果记录的错因，没有执行器结果的试次取平台原因码 | 网页、SDK、导出给出相同计数（06 第 6 节） |
| 结果记录中的错因 | M3：`trial_results.failure_cause` 存执行器原样上报的值 | 改存平台策略判定后的错因（例如没有可用奖励时为 `verifier_failed`），与试次的原因码一致 | 汇总按错因分组时不出现“已排除却没有原因” |
| 产物到期 | 07 第 2 节：试次终态 + 7 天 | 照此实现：试次终结时给其产物写到期时间，迟到的上传沿用同一时间；运行级产物从运行结束起算。M3 原先按写入时间起算，已改 | 不因上传延迟重新计时 |
| 回收与读 pin | 07 第 7 节 | 维护循环每 60 秒回收到期且没有有效 pin 的文件：先标 `deleting`，删文件，再标 `expired`（原因 `RETENTION_EXPIRED`），索引、摘要和评分保留；试次和运行的文件全部回收后产物状态记为 `expired`。只有导出取 pin（最长 1 小时，超时则导出失败并释放）；单个下载在读索引后立即打开文件，回收删除的是目录项，已打开的读取不受影响 | 下载不需要占用 pin，导出才需要跨多个文件的有界保护 |
| 下载 | 07 第 5 节：建议支持 Range | 未实现 HTTP Range；改为 `offset` / `length` 查询参数（单次最多 1 MiB，响应头 `X-Total-Size`），用于分页读日志。整文件下载改为流式 | 满足“有界分页读日志”的要求，实现简单；需要断点续传时再加 Range |
| 索引与文件对账 | 07 第 4 节 | 服务启动时、执行开始之前对账：索引为可用而文件缺失的标 `unavailable`（`STORAGE_CONTENT_MISSING`）；没有索引的文件和半写入的临时文件删除 | F-09；放在启动时做，避免把正在写入的新文件误判为孤立 |
| 批量导出 | 07 第 6 节 | `POST /exports` 受理后生成 Operation，由维护循环构建 ZIP。目录按设计，产物文件放在 `artifacts/<artifact_id>/<安全化文件名>`（原设计为 `artifacts/<artifact_id>`），任务目录名由服务端安全化生成。manifest 列出每个文件的摘要，缺失项给出原因（`EXPIRED` 带到期时间、`SAVE_FAILED`、`DELETED`、`STORAGE_CONTENT_MISSING`），摘要不符记为警告。导出包 24 小时后回收；超过 10 GiB 时预检失败。导出只有发起者和管理员可见；只读 PAT 也可以导出 | 保留文件扩展名便于直接打开；导出读取的是团队共享结果，按读权限处理，导出包本身是个人的 |
| 磁盘水位 | 07 第 7 节 | 按 `data_dir` 所在磁盘计算，阈值放在 `config.toml`（默认 20 GiB / 15%、10 GiB / 8%）。低于受理水位时新提交返回 503 `STORAGE_LOW`；低于派发水位时排队运行停在 `STORAGE_LOW`；查询、取消和下载不受影响。不因空间紧张删除未到期的证据 | F-10；阈值需按实际磁盘调整 |
| 删除的记录方式 | 07 第 8 节：回收站与删除回执 | 新增一张 `deletions` 表，每个被删对象一行：`recycled` 表示在回收站，`purged` 表示内容已删、此行即回执（记录名称、所有者、删除者和时间）。恢复时删除这一行，历史留在审计记录里。各业务表不加删除列，列表和选择器按此表过滤 | 一处判断“是否已删除”；不改动各业务表结构，减少与并行里程碑的冲突 |
| 物理删除的内容 | 07 第 8 节 | 运行：删除试次、执行尝试、结果、产物文件和快照，运行行留作回执，含该运行的导出包立即作废。数据集版本：删除任务定义、准入和不再被其他版本使用的任务材料，任务行保留任务键供历史运行显示；有排队或执行中的运行在用时拒绝。数据集：同时物理删除其全部版本。凭据：清除密文并释放名称，轮换主密钥时跳过。账户：清除密码摘要和会话，用户名保留且不可重新注册。PAT：令牌摘要作废。产物：删除文件，索引状态记为 `deleted` | 被引用的对象只留身份，引用方仍可显示“已物理删除” |
| PAT 的删除权限 | U-19 只规定成员可删除自己的运行 | 成员可在网页会话中删除自己的 PAT（立即撤销并从列表中消失），管理员可删除任何人的 PAT。原来 `DELETE /me/pats/{id}` 表示撤销，现改为删除，撤销改用 `POST /me/pats/{id}/revoke` | 成员本来就能撤销自己的 PAT，删除只是多一步隐藏；回收站的查看、恢复和物理删除仍只有管理员能做 |
| 凭据“在用”的判断 | U-19 | 查看排队或执行中运行快照里的 `provenance.credential_ids`。模型配置与凭据绑定属于 M5，届时须把绑定的凭据写进这个字段 | M5 之前没有运行使用凭据 |
| 删除范围 | 07 第 8 节列出的全部对象 | 已实现：运行、产物、数据集、数据集版本、凭据、账户、PAT。方案、批次、附件、模型配置、Harness、集合和分析快照在对应模块实现时接入同一框架 | 这些对象目前没有接口 |
| 删除数据集版本时回收准备缓存 | U-19 | 未实现：只删除任务材料。准备缓存、镜像归档和镜像在 M4 实现，合并时在 `recycle.purge_versions` 中接入（代码中有 TODO） | 准备缓存由并行的 M4 实现 |
| 导出与物理删除竞争 | 07 第 6、8 节 | 物理删除运行或产物时作废已完成的导出包；正在构建的导出在结束时复查，期间有相关内容被物理删除则构建失败（`EXPORT_CONTENT_PURGED`），不发布 | 独立审查发现：构建中的导出原先会在删除之后照常发布 |
| 最后一个管理员 | U-19 | 有检查，但实际由“不能删除自己”保证：执行删除的管理员本身就是另一个有效管理员 | 防御性检查保留 |

验证范围：服务测试 135 项通过，新增覆盖 06 第 6 节的计算例子、有效零分与无效奖励、全部排除时为 null、单样本无标准差、覆盖率、宏平均与 partial、重试只增加尝试数、用量的已知与未知数；产物按执行结束到期、回收后索引与评分保留、pin 有界保护与已打开读取不受影响、日志分段读取、启动对账（F-09）、磁盘水位（F-10）；E2E-OUT-01 的假执行器版本（只读 PAT 按版本和时间筛选运行、读汇总、导出并逐个核对 manifest 中的摘要，零分 / 缺评分 / 执行失败可区分，过期与保存失败带原因，导出包中没有 PAT 等秘密）；导出 pin 超时与超限失败、导出包到期；U-19 的各条删除规则与回收站（成员 / PAT / 管理员权限、排队运行不能删、恢复与物理删除、物理删除后运行返回 410 且回执可查、数据集版本在用时不能物理删除、凭据在用时不能删除且物理删除后名称可复用、账户删除后会话和 PAT 立即失效、恢复后可登录但 PAT 仍为撤销、用户名保留）。真实 Docker 测试 4 项照常通过，前后镜像与容器数量不变。网页：`npm run build` 与 `npm run lint` 通过（只有与已有页面同类的警告）；在全新演示实例上用 Playwright 走过运行列表评分列、运行汇总、导出与下载、PAT 撤销与删除、删除运行 → 回收站 → 恢复 → 彻底删除 → 回执，脚本在 `frontend/qa/smoke.spec.ts`，仍未进入自动门禁。环境：服务 CPython 3.13，Runner CPython 3.12.3 + Harbor 0.24.0，Docker 29.9.1，Linux 6.8。

交给 M4：导入数据集时须检查 `deletions`。目前登记同一内容会返回已物理删除的旧版本，被删数据集下的新版本也会被隐藏；导入在事务外安装任务材料，与物理删除并发时材料可能被删。

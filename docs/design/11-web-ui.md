# 11 网页信息架构与交互

阶段：P0 / P1 · 来源：三个用户故事与贯穿要求

导航：[总览](00-overview.md) · 依赖：[配置](03-configuration-attachments.md)、[API](10-api-sdk-cli.md)、[权限](09-identity-security.md)

## 1. 页面结构

| 页面 | 主要内容与操作 | 阶段 |
| --- | --- | --- |
| 工作台 | 本人近期运行、团队近期结果、待处理错误、系统可受理状态 | P0 |
| 数据集目录 | 来源、版本、已准入 / 可提交 / 缓存就绪任务数、作者参数、资源要求 | P0 |
| 数据集详情 | 准入、内容可得性、本机缓存与上次恢复错误；管理员首次准备及其重试入口 | P0 |
| 实验方案 | 团队方案、本人编辑 / 复制 / 归档、修订历史 | P0 |
| 新建运行 | 配置、任务选择、资源、最终值与来源、预检和提交 | P0 |
| 运行列表 | 按数据集、模型、Harness、附件、提交者、时间、状态筛选 | P0 |
| 运行详情 | 多维状态、配置、任务结果、日志、产物、来源与后续操作 | P0 |
| 提交批次 | 展开配置、总规模、每运行进度、取消未完成部分 | P0 |
| 附件 | 组件、影响范围、版本、兼容性、上传与校验 | P0 |
| 导出中心 | 导出进度、缺失项、下载入口、包到期时间 | P0 |
| 实验集合与比较 | 集合成员、关注因素、任务对齐、条件差异、结论与快照 | P1 |
| 个人设置 | 账号、PAT 创建 / 撤销、有效期、额度、使用记录 | P0 |
| 管理设置 | 成员、模型、Harness、凭据、默认值、配额、保留策略 | P0 |
| 维护 | 健康、日志、版本；更新、排空、备份与恢复 | 基础 P0，其余 P1 |

网页采用 React + TypeScript，Vite 构建静态文件，由 FastAPI 服务托管；生产主机无需 Node。业务客户端由公共 OpenAPI 生成，页面不通过模板或私有旁路执行 SDK 无法表达的业务动作。管理员动作保留网页会话限制；视觉规范与组件库待实现阶段选择，尚无前端工程。

## 2. 新建运行流程

~~~mermaid
flowchart LR
    A[选择方案或直接配置] --> B[数据集版本与任务]
    B --> C[模型、Harness、附件]
    C --> D[资源、试次数、总时限]
    D --> E[服务端解析与预检]
    E --> F{存在阻塞项}
    F -->|有| B
    F -->|无| G[确认配置与差异]
    G --> H[幂等提交]
    H --> I[运行或批次详情]
~~~

配置区先预填作者预设，显示团队默认和方案影响；最终确认页显示每项生效值与来源、偏离作者基准、完整 bench 覆盖范围、预计试次数和 PAT 额度影响。

单击提交生成并持有一个幂等键，在本次逻辑提交结束前保持不变；超时或刷新后先查询已受理记录。用户明确选择“再运行一次”才生成新键。按钮防重复点击仅改善交互，服务端幂等才负责一致性。

默认选择“全部可提交任务”（all_eligible）时，已准入的冷缓存任务也在范围内，确认页显示完整 bench 中被排除的任务及原因。任务行分别显示“已准入 / 未准入”“缓存就绪 / 运行时恢复缓存”和“上次恢复错误”，缓存缺失或一次恢复失败不能让勾选框自动失效。

首次准备未成功、必要配置不完整、显式撤销或确切内容不可得时禁选，并列出对应原因和权限允许的下一步；管理员可处理首次准备或添加新版本。暂态恢复失败在关联试次显示受限自动重试与“创建新重跑”，不一律引导联系管理员。缓存恢复提示说明可能增加等待时长，仍受总时限和全局存储水位限制。

## 3. 运行详情布局

| 区域 | 必须展示 |
| --- | --- |
| 顶部摘要 | 身份、创建者、PAT 标识、来源、批次、受理 / 开始 / 结束时间 |
| 进度 | 队列、共享缓存等待 / 恢复、试次安装、执行、验证、收集计数与等待原因 |
| 状态卡 | 生命周期、已评分覆盖率、产物保存、环境清理 |
| 配置 | 不可变生效配置、来源、内容摘要、作者基准差异、实际偏离 |
| 任务表 | task_key、计划 / 已评分试次数、指标、通过状态、错因 |
| 试次详情 | 阶段、执行尝试、日志、会话、验证输出、产物目录 |
| 操作栏 | 取消、原配置重跑、失败任务重跑、修改后运行、导出 |

不要用单一绿色“成功”覆盖产物失败或清理失败。评分为 0 显示“0”；未评分显示“未评分”及原因；费用未知显示“未知”。清理失败作为可处理事项单列，不让它遮挡已有结果。

配置、日志、原始文件按需加载；列表默认有界分页，不因单个大型日志阻塞整个运行详情。

共享恢复展示关联 Operation、阶段和本运行等待时间；取消按钮作用于本运行，说明其他等待运行继续。bootstrap 安装日志归属本试次，失败不把数据集目录改成“未准入”。重跑预检允许自动恢复原 digest；确认无法取得原内容时展示具体摘要及阻塞原因。

## 4. 成组提交与后续操作

批次预览呈现完整展开列表、运行数、计划试次数、额度消耗和逐项阻塞，只有全批通过才可提交。取消批次说明已获分结果继续保留，未完成部分停止。

重跑确认页只允许选择任务子集，并显示“创建新运行”；需要修改参数时进入“修改后运行”。失败任务选择按任务粒度展开，显示哪些重复试次失败以及将重新执行的完整次数。

修改后运行展示与来源快照的字段差异；成功后详情页链接父运行。P1 可选择将新运行加入本人可写集合。

## 5. 个人 PAT 与管理员交互

创建 PAT 时显示 scope、有效期和总提交运行上限，并说明批次按实际运行数扣减。token 只展示一次，离开页面后仅显示前缀、期限、使用量和撤销按钮。

管理员配置页只显示脱敏凭据引用，替换凭据采用新值输入，不提供“显示原值”。参数变更显示是否需要重启、影响哪些后续运行，禁止给出“已更新所有历史实验”的文案。

维护页区分进程存活、可受理、具体运行阻塞；维护受理后返回持久操作身份，页面断线后可重新查询。P0 未实现的更新 / 恢复按钮不显示为可用。

## 6. 待处理事项

“待处理”是业务记录的查询视图，P0 不新增独立待办系统。包括：管理员首次准备失败、确切内容不可得、运行恢复 / 附件安装失败、不可执行的排队运行、需重跑的中断任务、上传 / 清理失败、即将到期证据及维护失败。区分管理员准入操作和提交者可重跑的运行错误。

每项给出来源对象、错误码、发生时间、可执行动作与权限。成员无法处理管理问题时显示受阻原因；管理员进入对应设置。是否已处理由源对象状态决定，不能用手动勾选掩盖仍在发生的错误。

## 7. 交互验收

- 网页配置解析与 SDK 得到相同摘要；字段错误定位到具体输入。
- 刷新页面或客户端断线后能找回操作，提交不会重复启动。
- 无障碍文本不依赖颜色；0、未知、失败和过期可直接区分。
- 不能执行的动作有明确原因；服务端仍独立校验权限。
- 到期产物与清理失败在运行详情可见，已评分结果仍能正常阅读。
- 缓存回收后已准入任务仍可勾选；默认范围包含冷缓存任务；页面能区分首次准备失败、暂态恢复失败和原内容不可得。

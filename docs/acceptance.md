# 首版验收清单

每项记录实际命令、结果与证据位置；尚未做的标未验证。主编排者只在机器验收和所需人工验收完成后汇总通过。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| A1 | 新成员使用入口 | 干净的 Python 环境按说明安装；默认方案无需改脚本，缺依赖的诊断给出修复动作且不调用模型 |
| A2 | 固定数据集 | `au12321ua/cad-bench` 实际解析成固定 revision/任务身份；真实 Harbor/Docker oracle 产生 verifier reward 和产物，不使用 mock 代替 |
| A3 | 后台执行 | 提交进程/模拟 SSH 会话退出后 Job 继续执行，重新打开 CLI 能查询同一 run |
| A4 | 多成员与总容量 | 两个独立 CLI 同时提交得到不同 run/工作区；全局配置限制活动 Job/Trial 总量，其他实验排队 |
| A5 | 取消 | queued 与 running 均可取消；本次进程/容器停止，原始证据保留，另一个 Job 不受影响 |
| A6 | 故障与状态 | 模型/安装/verifier/worker 故障可定位；异常不被算有效零分或 succeeded；worker 意外退出不永久 running、不造成双重执行；未清理或未计入容量的残留任务不能因锁释放而被忽略 |
| A7 | 报告与对比 | 输出逐任务 reward/异常/证据；相同任务来源可对比候选，任务/评分条件不兼容时拒绝或明确标注 |
| A8 | bundle 和重跑 | 提交后改源 bundle 不影响原 run；运行确实使用快照版本；rerun 新建记录，原结果不变，来源不能固定时明确失败 |
| A9 | 凭据与版本 | 配置/argv/日志/报告不泄露凭据；CLI/worker 实际 Python 与加载的 Harbor 0.23.0 可核对；记录实际可取得版本，未知不虚报；不自动读取相邻项目 secrets |
| A10 | opencode 接入 | 使用维护者配置的模型完成至少一次真实任务与评分；无模型时明确未验证，不能拿 oracle/mock 替代此项 |
| A11 | 成员验收 | 未参与搭建者照说明提交、断开后查结果、对比和重跑，无维护者代改脚本；需用户参与时准备好步骤后暂停 |

报告不要求候选评分必然高于基线。Oracle 验证执行与 verifier，模型实验验证成员的实际使用链路，两者用途分开。

A6/A7 额外覆盖：原生 `exception_info=null` 但 agent 非零退出、目录复制成功却提交物缺失的情况。退出事实、框架异常和原始 reward 分别报告；任务行为失败按 benchmark 规则处理，不统一归为基础设施错误，也不靠 CAD 私有错误文本作通用分类。

A6/A7 的损坏结果检查包含 `task_name=3` 与数值 reward `10**400`：报告应返回明确诊断并同步运行状态，保留原文件，不发生未处理异常，不将错误值转为有效零分。对照的合法 reward=0 仍应计为有效尝试。

A2 的 runtime 兼容证据与产品验收分开：固定源码/skill、构建输入及实际 image ID；同镜像 agent/verifier 的原 box、cylinder 正例与 `BOX_WIDTH=61` 负例验证评分有效。独立 Trial 通过后，还须通过交付版本的 helper CLI 完成两题执行、报告以及 A7/A8 的成功实验对比与 rerun。

A9 的模型凭据路径须用假标记检查实际进程 argv/env：值只能进入明确的运行时环境，不能进入 argv 或持久化记录。脱敏覆盖流式跨块写入、原生执行证据、根级报告、异常原因与相关调度记录；worker 硬退出后的恢复/清理不能绕过检查。数据库字段在写入前处理，不对 SQLite 或冻结输入做字节替换。真实证据在扫描确认不含凭据后才交接，扫描只报告安全结论。

A6/A9 的容器日志权限边界：只读目录中的 clean 文件不要求写权限，不创建替换文件、不改变 inode/mtime；若确实命中凭据却无法清洗，或无法确认扫描完成，仍保留 cleanup_blocked 和容量，不交接原始证据。

## 真人反馈后的使用说明检查

用户优先要求澄清 API key 注入与模型提交、精简 README。A1/A11 的说明应让成员从 README 找到：非秘密模型配置、受保护 key 文件的准备与注入、首次调度器凭据刷新、显式模型提交，以及重连后的查询。明确裸 `submit` 的默认 oracle 行为，不能将 oracle 自检或 `doctor` 成功描述为模型认证成功。

README 专注功能、环境配置、运行步骤和文档导航；构建、设计、实现与验收证据链接到配套文档。查询示例与取消、重新执行示例分开。固定文档版本可用参数解析、代码块语法和本地链接检查验收，不因此追加模型请求；实际可用性仍需用户复试确认。

命令输出美化列为后续需求，本轮不以文档修正宣称该项已经解决，也不以机器人审查代替真人 A11。

## 原生 CLI 可用性修订验收

用户后续授权用代码完善；本轮包括一次登录、普通模型提交、观测输出与停止/恢复/扫描封装。上一轮文档通过保留为历史，不能代替这些行为。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| U1 | 一次登录与重连 | 正式 auth login 隐藏输入或引用保护文件，默认限时保存；新 CLI 进程自动使用所选 team/凭据，无 hh_* 函数或重复注入 |
| U2 | 普通提交 | 裸 submit 选择模型；缺模型/登录在下载、创建 run 或启动 worker 前明确失败；oracle 显式选择，旧 run/rerun 身份不改 |
| U3 | 到期与活动任务 | 到期拒绝新提交与实际出队；到期排队任务明确未执行失败；活动任务继续并完成审计，查询/取消不被禁用 |
| U4 | 凭据轮换与保护 | 0700/0600、所有者/普通文件/非链接校验；轮换/logout不丢审计 key，argv/配置/日志/报告不泄露；登录不发认证探测 |
| U5 | 调度器封装 | 登录自动刷新旧 idle scheduler；stop核对PID+birth并等待退出、超时失败；recover加载所需审计凭据，不依赖用户等待函数 |
| U6 | 扫描与清理 | 正式 scan只输出计数/结论；保留停写后扫描、精确资源清理、不可审计不放容量的现有要求 |
| U7 | 观察与输出 | list/status/logs/report正常观察；默认摘要/表格可读，--json保留结构/退出码，项目脚本显式选择JSON，无需借shell处理 |
| U8 | 日常说明 | README只用正式CLI展示安装、一次登录、提交和观察；辅助函数/内嵌Python退出使用流程，用户复试结果单独记录 |

测试以假凭据、隔离目录、多真实 CLI 进程、无付费 fixture和必要oracle完成。不得为本轮自动新增模型请求、复制已指定真实凭据或改变题目/评分；历史A9/A10保留，新登录可用性需独立证据和用户反馈。

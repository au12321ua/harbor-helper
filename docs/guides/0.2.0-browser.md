# 升级后的浏览器体验

本指南适用于部署者完成 0.2.0 升级后的服务。实际入口版本需由部署者核对。成员无需登录服务器。管理员预先配置并验证数据集、任务、agent/模型与团队凭据；这里不指定真实付费模型，不代用户发实验。

1. 用管理员邀请的账户登录；在“新建实验”(`/new`) 选择已验证的小任务。先确认就绪、本人额度和实验授权，固定数据集版本、任务、agent/模型、尝试次数、并发、时限及评分条件。模型预算需另行确认，额度不是金额保证。
2. 在“团队附件”(`/attachments`) 查看已发布版本；同一固定条件分别建三组：明确“无附件”、明确 v1、明确 v2。避免选择会移动的名称作为版本解释；记录每组冻结引用。附件准备/发布与限制见[附件指南](attachments.md)。
3. 从“共享实验”(`/`) 打开各组详情，查看“配置与状态”“评分报告”“运行日志”；安全报告可用后实际下载。有效零分、缺评分、执行失败分别判断；报告被审计阻断时不要用其作效果结论。
4. 在“实验对比”(`/compare`) 选无附件与 v1，再选 v1 与 v2；先读可比性检查，确认其他条件相同。报告中的 fixture 分数只验证流程，不代表真实 LLM 效果。
5. 对自己尚未终态的任务使用详情页取消；成功记录可重跑，新的提交归本人并保留父历史。重跑前核冻结条件/版本和就绪；结果全团队共享，不能取消他人任务。

管理员在“团队管理”(`/admin`) 管理成员额度与全局容量，维护区暂停新受理、观察已受理队列/运行并按需要排空，再恢复受理。暂停不会停止已受理任务，也不代表可立即备份；完整停写见[升级交接](0.2.0-upgrade.md)。成员在“自动化凭证”(`/access-credentials`) 按用途签发/撤销自己的凭证；管理员治理团队凭证与容量。只读和执行权限按页面/API能力区分，不把 token 写到聊天或日志。

委托研究 agent 时按[研究 skill 指南](research-skill.md)复制完整独立 skill 目录到自己选定位置；该指南链接 CLI 安装和私有文件/stdin 凭证配置。不会默认全局安装，也不自动授予执行或真实模型预算。API 详情见[自动化契约](../reference/automation-api.md)。

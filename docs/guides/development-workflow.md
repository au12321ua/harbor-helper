# 开发、协作与发布

项目采用轻量的 `feature → dev → master + tag` 流程。开发使用独立分支和工作树，正式服务运行固定发布版本。

## 分支职责

| 分支 | 用途 |
| --- | --- |
| `master` | 已验收的发布主线；日常开发不直接在此提交，也不在部署目录编辑源码。 |
| `dev` | 下一阶段的集成分支；功能、修复和文档修改从这里开始。它不等于生产部署版本。 |
| `feature/<topic>`、`fix/<topic>`、`docs/<topic>` | 单项工作的短期分支；每个成员或bot使用自己的工作树。 |

暂不常设 `release/*` 或 `hotfix/*` 分支。确有并行维护稳定版本或紧急发布需要时，再按当次任务确定流程；从发布版本修复的变更也应回到 `dev`，避免后续发布丢失修复。

首次建立 `dev` 可从现有已发布的 `master` 创建；本指南以独立文档分支作为初始化修改，不移动已有部署的 `master`。

## 开始一项工作

先读[开发交接](../HANDOFF.md)和当前任务。已有工作目录有未提交修改时，保留现场，另建工作树；不要为切换分支清理或覆盖别人的修改。

确认远端 `dev` 存在后，在自己的仓库执行以下示例；工作树路径与主题名按本次任务选择，不复用其他人的目录：

```bash
git fetch origin
git worktree add -b feature/my-change ../harbor-helper-my-change origin/dev
cd ../harbor-helper-my-change
git status --short --branch
```

后续修改、构建和验证都在这项工作的工作树内。前端构建会更新包内 `static/`，应与对应前端源码一起交付。测试须沿交接的独立HOME/state/凭据隔离要求执行，不能使用正式团队state作随手测试。

提交前按影响范围完成必要检查，再推送自己的分支：

```bash
git diff --check
git add -- path/to/changed-file
git commit -m "Describe the change"
git push -u origin feature/my-change
```

## 集成与多人或多bot协作

- 以PR/MR（目标 `dev`）交付单项工作，说明可观察变化、固定提交、实际验证及未覆盖范围。暂时无法使用PR/MR时，负责人也应基于同样的固定提交与证据完成审查后集成。
- 不共用一个checkout写文件，不修改其他工作树的分支或未提交内容；一项任务的负责人负责自己的提交和冲突处理。
- 集成前核对最新 `dev` 与候选提交。出现相关代码变化或冲突时，验证受影响的行为；旧提交的检查结论不能自动作为合并后版本的结论。
- 只合并必要修改；需要的工程审查和独立验收按任务影响范围安排，不因文档排版等低影响修改机械调用完整产品测试。
- 不改写已共享的 `master`/`dev` 历史，不强制推送；个人分支已被别人使用时，重写前先协调。

这些是协作规则，不表示远端已配置分支保护、必需检查或自动CI。不能把尚未配置的保护当作已经生效。

## 发布与运行版本

1. 选定 `dev` 的固定候选提交，完成该版本需要的验证；之后若候选内容变化，补验受影响的部分。
2. 将已验收候选集成到 `master`，为最终发布提交创建不再移动的版本tag（例如 `v0.2.0`）。tag、包版本、前端构建产物与依赖锁应对应同一发布；例子不是本轮已发布的版本。
3. 记录发布提交、构建标识、检查范围及迁移要求。正式服务从独立发布目录启动，固定到commit/tag；不通过部署目录的日常编辑或自动拉取来跟随 `dev`。
4. 服务state和外置主密钥独立于发布物。上线前核活动任务、资源与所有写者，按[Web维护指南](web-service.md)执行合适的升级和恢复步骤。

数据库升级后的回退需要单独说明数据兼容或恢复路径；代码回退不代表state可以回退。旧备份不能覆盖后来新增的业务数据。现存已部署checkout在迁移到独立发布目录之前继续按现场保护说明维护，不能直接切分支或移动目录。

## 开发计划与工作入口

当前开发计划放在项目飞书群的版本化记录中：每个实质版本发布完整正文和变更摘要，保留旧消息，群内置顶和项目进度卡指向当前版本。开始工作时读取最新版本及本次明确任务，不把历史想法当作已批准的实施范围。修改示例中的 `path/to/changed-file` 等参数时，替换为本次实际文件和主题。

仓库记录通用协作与发布规则，不维护另一份本地开发路线。botmux本地白板仅作当前计划入口和维护摘要；同机共享不保证跨主机可读。无法访问群记录的协作者应取得当前版本内容，不能根据旧本地副本猜测任务。

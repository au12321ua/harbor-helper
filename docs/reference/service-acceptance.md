# 团队共享实验服务验收标准

本页定义团队服务的通用验收行为。每项结论须另行记录固定产品版本、前置条件、实际过程与未覆盖范围；标准不是运行报告。

共享、权限、凭据和HTTP边界见[服务设计](../archive/team-service/service-design.md)，运行步骤见[服务指南](../guides/web-service.md)。

每项记录固定产品版本、实际过程、结果和证据。先使用隔离服务state、假key、无网络边界与简单数据集oracle；真实模型验证另需明确预算，不以运行时长/并发上限承诺金额。全体成员共享结果，验收不再包含成员间 private 结果隔离。

| ID | 场景 | 可验证的通过条件 |
| --- | --- | --- |
| S1 | 团队身份与归属 | 管理员创建受邀本地账户（可适配现成登录）取得稳定身份；未邀请/未登录者不能使用团队API；提交者由服务端填写，篡改请求user_id不能冒充他人。按人统计有可靠归属，历史未知提交者不伪造。 |
| S2 | 全团队共享查看 | A创建的受理/run出现在B的CLI和Web；B可查看状态、日志、完整安全报告、产物并选择比较。列表不默认按owner裁剪，无private设置；按提交者筛选仅是展示。管理员凭据值始终不随共享记录公开。 |
| S3 | 多提供商、多key与方案 | 至少两个提供商、其中一个至少两个不同假key；至少三个模型方案明确映射对应组合。方案引用错误提供商的凭据被拒绝。真实Worker边界核对endpoint/协议/模型/key选择准确；并发任务无串用，无暗中改key/提供商。 |
| S4 | 凭据管理与加密 | 管理员新增/轮换/停用key，普通成员管理请求被拒绝；创建响应与元数据查询无key明文/密文/主密钥，前端不反填或持久保存key。假key明文不进入数据库/WAL、请求或执行日志、argv、快照和产物。DB外服务账号拥有的0600主密钥可解密合法来源；仅有DB备份不能取回明文，错误/缺失主密钥明确失败且无旧env兜底。 |
| S5 | 提交时固定配置 | 受理后修改提供商endpoint、方案模型/参数、默认数据集或凭据当前版本，已有任务非秘密配置与绑定不变；实际解析dataset/task digest、bundle与环境固定。记录凭据ID/版本，不写值或密文进manifest。 |
| S6 | 执行前凭据检查 | 入队后停用或损坏绑定凭据，实际出队及Worker启动边界不执行模型，明确未执行失败。不能回退oracle/其他key；登录成功或可解密不冒称远端认证通过。已运行任务保持收尾审计；缺审计来源仅标记异常并限制展示，资源已清理则释放容量。 |
| S7 | 幂等与准备中取消 | 同一成员同一操作同键同内容的并发/超时重试只形成一个受理/run；同键不同内容冲突。准备失败不形成可运行假run；准备中取消权限同任务取消，重启/下载完成竞态不留下可执行孤儿。不同成员/主动新rerun是独立操作。 |
| S8 | 共享观察与取消边界 | B可读A任务但取消A任务返回403，实际任务不受影响；A可取消自己的queued/running/preparing；管理员可取消任何成员任务。反复取消不影响其他run，清理确认后才显示cancelled。不可仅依赖前端按钮。 |
| S9 | 跨成员重跑 | B重跑A任意团队实验，新受理/run提交者为B、parent为A原run，原记录和固定输入不改；B可取消新任务，不能取消A原任务。保留原模型/实验配置，当前匹配凭据重新绑定检查；不可用时明确拒绝，不能改成最新方案。 |
| S10 | 持久队列与恢复 | 关闭网页/CLI、重启API、准备进程/调度器/Worker硬退出后，受理和队列仍可追踪；不会双执行或永久假running。只有精确资源清理未确认时保持cleanup_blocked/容量；单独审计异常不阻塞队列，其他任务按统一上限排队。 |
| S11 | 全局限制与统计 | CLI/Web多个成员并发提交时共享同一Job/Trial计数；墙钟、尝试、CPU/内存及队列/上传限制实际生效。统计区分提交者，时长/token字段有观测来源；未知费用unknown，不把reported cost0或时长/并发称为准确金额保证。 |
| S12 | 评分与比较 | 合法reward=0仍有效；缺尝试、缺评分、框架/执行失败不转成有效0或成功；两入口显示一致。条件/数据集不同明确不可比、无聚合改进；同快照rerun可比，不改原评分器或加入CAD专属逻辑。 |
| S13 | 日志与产物共享/删除 | 全成员取得同样的脱敏日志和安全产物；键/编码/跨块泄露检查通过，缺审计来源给全团队覆盖限制。普通成员删除请求403；管理员仅删除终态且清理确认后的产物，有操作者/时间及已删除标记、重复删除幂等；固定任务/bundle/评分/报告/审计不被破坏，任意宿主路径拒绝。 |
| S14 | 前端栈与同服务HTTP | 构建使用Vite+React+shadcn/ui+Tailwind，停止Vite开发服务后，一个HTTP应用可按配置host/port提供静态文件和API。依次更改监听地址/端口后访问同一构建产物，API请求为相对路径且无写死域名/CORS依赖；SPA详情刷新正常，API错误保持JSON，缺静态资源正确404。无需内置HTTPS/Nginx/证书/域名配置。 |
| S15 | CLI/Web一致与操作 | A用CLI提交、B在Web查看，B用Web重跑后在CLI查看和取消自己的新任务；Web五页覆盖选择数据集/方案/bundle、日志/报告/产物、compare、管理。网络断开/刷新不把旧状态当成功；服务不可用不静默本地执行；普通成员不需SSH/state/调度器脚本。 |
| S16 | 清理与审计解耦 | 缺旧key时资源确认释放、容量计数下降、后续其他key/oracle可运行；相关日志/报告/产物拒读、摘要展示audit=incomplete。真实资源清理失败才cleanup_blocked。主密钥整体失效不冒称其他加密key可用。 |
| S17 | 最小账户与版本保留 | 本地登录无开放注册，成员/admin实际API权限正确；旧版本无运行或保留日志审计依赖时回收，依赖存在时保留。归档安全报告仍可看，过期原始日志给410，不修改固定输入。 |

## 必须记录的对照

- **共享与操作权限是两个维度**：B读取A成功、B取消A失败、管理员取消A成功；B重跑A后取消新任务成功。读取权限不是逐成员隔离。
- **两个提供商与三份key**：使用互不相同的假标记，核对匹配的Worker环境和实际出队配置，保证API并发不靠修改进程全局env换key；日志只记录安全核对结果。
- **轮换与审计**：新受理绑定新版本，已有记录保留旧版本；显式撤销旧版阻止未启动任务，旧审计来源仍受保护。被引用版本物理删除返回冲突，不能伪称彻底清除。
- **同HTTP入口**：改变host/port无需重建前端或配置域名；身份验证、API路由与SPA fallback各自正确。数据库加密不等同HTTP传输加密，部署环境的TLS/代理不作为服务内置验收项。
- **真实与替代边界**：假key/无网络执行边界验证选择和恢复；简单Hub/Docker oracle验证实际任务/评分/清理；这些都不替代真实提供商认证或模型能力证据。

## 运维与兼容边界

数据库备份不包含主密钥；另有受保护的主密钥恢复说明。恢复验证检查队列、配置版本、绑定与审计能力，不以空队列或假凭据冒称旧任务可恢复。产物保留参数由管理员配置，清理不能删除未终态输入或历史审计依赖。

历史模型/数据集证据按原版本解释；旧本地CLI已移除，其记录不导入服务。机器验收与真实成员试用分别记录；真实模型和部署操作须有对应授权。


主密钥轮换验收需单列全历史模型/Hub重加密、空实例KCV、单SQL读快照间隙、多进程压力、fsync顺序及提交前后进程中断恢复。SIGKILL只证明进程恢复，不能作为断电实测。缺active/文件/权限/KCV故障应保留queued并显示全局就绪错误；ops校验配对快照与新目标只读恢复，热journal失败关闭。

模型协议验收分别验证Chat Completions、Responses、Messages的实际锁定OpenCode请求路径、鉴权、每项支持参数/输出上限、流式文本、完整工具往返和usage；另用假key独立Docker微任务验证helper到Harbor、容器和协议服务链路。配置覆盖负例含bundle/project/.opencode/global jsonc及model/small_model/SDK/auth，重跑的当前协议/端点与冻结值不等价时409。上述条款是验收要求，不代表任意版本已通过。
